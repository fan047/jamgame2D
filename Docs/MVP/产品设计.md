# Holedown 类 Jam MVP：产品设计

日期：2026-10-30。本文记录本次访谈已确认的产品范围，供策划、程序及执行 agent 使用。

配套文档：[技术方案](技术方案.md)。开发以已确认的轻量分层、组件组合和有限状态机架构为准。

**执行要求：每完成一个独立、可验证的改动，必须先进行对应自测；通过后提交一次 Git，再开始下一项。关卡参数、Prefab、配置和文档修改也适用。具体流程见技术方案第 7 节。**

## 1. 目标与交付

团队为 1 程序、1 策划、2 美术。首版在一个工作日内完成，以 8 个有效开发小时规划，包含自测、提交和构建时间。

核心体验：**选择角度，让一串球进入缝隙、反复撞击，并连续击碎数字方块。**

交付内容：

- 一个可在 Unity 中直接 Play 的灰盒场景。
- 一份可在 Inspector 中编辑的预设短关卡。
- 一个可独立启动、完成对局和重开的 Windows 运行包。
- 运行方式、参数说明、自测结果及相关 Git commit hash。

运行环境锁定 Windows、鼠标、单人游戏、竖向棋盘。首版使用占位图形完成完整小局。

## 2. 核心循环与规则

**观察布局 → 瞄准 → 连续发球 → 反弹扣血 → 回收或召回 → 回合结算 → 棋盘推进 → 下一轮或结束。**

| 项目 | 确定规则 |
|---|---|
| 瞄准 | 鼠标移动瞄准，左键单击发射；发射前显示截至首次碰撞的瞄准线 |
| 发射点 | 位于棋盘上方，整局固定 |
| 连续发射 | 点击时锁定方向，固定数量的球按固定间隔依次射出 |
| 球的运动 | 无重力、匀速；左右墙和底墙反弹；球之间不碰撞 |
| 自然回收 | 球向上越过顶部回收线时回收 |
| 方块 | 仅单格和横向双格矩形；一次有效碰撞扣 1 血，归零立即失去碰撞并消失 |
| 飞行期间 | 不接受新的瞄准发射命令，可点击召回按钮 |
| 手动召回 | 取消尚未发出的球、回收全部活动球，保留已造成的伤害，正常结算 |
| 自动兜底 | 本轮超过 30 秒游戏时间时，执行与手动召回相同的流程 |
| 棋盘推进 | 每轮结束后，剩余方块上移一格，底部补入下一条预设行 |
| 胜利 | 最后一条预设行包含唯一目标块；击碎目标块后在本轮结算时获胜 |
| 失败 | 推进后，任何方块进入顶部危险区域 |
| 重开 | 胜负界面提供重开按钮，恢复关卡初始状态 |

预设行耗尽后，每轮仍继续上移，底部不再生成新块。普通方块全部消失不会提前判胜。

### 2.1 结算顺序

1. 待发射数量和活动球数量都归零，才允许结束本轮。
2. 检查目标块是否已被击碎；若是，判胜并停止推进。
3. 否则将剩余方块上移一格，并补入下一条预设行。
4. 检查危险区域；若有方块越线则判负，否则进入下一轮瞄准。

同一轮只能结算一次。击碎目标后仍先完成回收或召回，再显示胜利。

### 2.2 场地与参数默认值

以下为首版执行默认值；球参数、血量及合法布局可以在 Inspector 中调整。数值尚未经过实机平衡验证。

| 参数 | 默认值 |
|---|---|
| 棋盘尺寸 | 8 列、8 个安全行；单格为 1 世界单位 |
| 坐标约定 | 左下角为 `(0,0)`；列从左向右，行从下向上；安全行编号为 `0–7` |
| 危险区域 | 方块行号达到 `8` 或以上；危险线绘制在 `y=8` |
| 发射点 | `(4,9)` |
| 顶部回收线 | `y=9.6`，仅向上越线时自然回收 |
| 场地内侧边界 | 左墙 `x=0`、右墙 `x=8`、底墙 `y=0` |
| 每轮球数 | 12 |
| 球半径 | 0.12 世界单位 |
| 球速 | 12 世界单位/秒 |
| 发射间隔 | 0.08 秒 |
| 瞄准范围 | 相对正下方左右各 75°；有效方向超出范围时限制到边界 |
| 无效瞄准 | 鼠标位于发射点上方、与发射点重合、位于游戏区域外或覆盖交互 UI 时，不允许发射 |
| 方块间隙 | 相邻格之间留 0.1 世界单位；视觉与碰撞体尺寸一致 |
| 自动召回 | 自本轮接受发射起，累计 30 秒游戏时间 |
| 默认窗口 | 720×1280；其他窗口比例保持棋盘比例并保证完整可见 |

单格方块中心为 `(列号+0.5, 行号+0.5)`；双格方块中心为 `(起始列+1, 行号+0.5)`。单格尺寸为 `0.9×0.9`，双格为 `1.9×0.9`。

## 3. 默认演示关卡

每个条目用 `(起始列, 宽度, 血量)` 表示，所有方块高度均为一格。初始第 0 行在底部；补行按表中顺序逐轮加入底部第 0 行。

| 布局位置 | 方块 |
|---|---|
| 初始第 0 行 | `(0,2,5)`、`(3,2,4)`、`(6,2,5)` |
| 初始第 1 行 | `(0,1,3)`、`(2,1,3)`、`(5,1,3)`、`(7,1,3)` |
| 初始第 2 行 | `(1,2,4)`、`(5,2,4)` |
| 初始第 3 行 | `(0,2,3)`、`(6,2,3)` |
| 第一次补行 | `(1,1,3)`、`(3,2,4)`、`(6,1,3)` |
| 第二次补行 | `(0,2,4)`、`(6,2,4)` |
| 第三次补行 | `(1,2,4)`、`(5,2,4)` |
| 第四次补行 | `(3,2,10)`，标记为唯一目标块 |

这是可运行的调参起点。策划负责验证反弹空间、顶部压力和胜利路线，调整时保持既定基础规则。

## 4. 界面与反馈

### 4.1 游戏中

- HUD 显示当前回合、活动球数、预设行进度。
- 召回按钮仅在发射及飞行阶段可用；瞄准线仅在可发射且方向有效时显示。
- 普通块显示数字血量，目标块使用独立颜色及标记。
- 危险线始终可见，发射点与棋盘边界清楚可辨。
- 灰盒采用 TMP 默认字体支持的英文短标签，例如 `Round`、`Balls`、`Recall`。

### 4.2 声画表现

- 有效命中：短暂闪白，数字立即刷新，播放简单碰撞音。
- 击碎：立即禁用碰撞体，播放少量碎片；碎片不参与游戏碰撞。
- 多球密集命中时碰撞音统一限频，最短间隔 0.05 秒。
- 闪白、缩放、音效和粒子不改变血量、实际碰撞形状或结算时机。

### 4.3 胜负界面

- 胜利显示 `Victory` 和 `Restart`。
- 失败显示 `Defeat`、原因 `Blocks reached the danger line` 和 `Restart`。
- 结束后停止接受发射命令；点击重开恢复所有初始状态。

## 5. 代表性操作场景

| 场景 | 预期结果 |
|---|---|
| 玩家将一串球射入方块间的空隙 | 球反复撞击，逐次扣血并击碎方块，数字与反馈及时更新 |
| 先发出的球已回收，但还有球尚未发射 | 本轮继续发球，棋盘不提前上移 |
| 玩家在连发尚未完成时点击召回 | 后续发射停止，活动球被回收，伤害保留，只推进一次 |
| 目标已击碎，而本轮推进原本会导致顶部越线 | 回收完成后直接判胜，不再推进 |
| 方块推进进入危险区域，随后玩家重开 | 显示明确失败原因；重开后恢复初始布局，没有旧球或旧回合效果 |

## 6. 范围与团队分工

本版包含瞄准、连续发射、反弹、数字块、召回、预设补行、完整胜负、重开、配置和最低声画反馈。

后续版本再考虑：支撑坍塌、异形块、随机生成、球数成长、特殊能力、升级、商店、存档、多关卡、移动端、正式美术接入和本地化。

| 角色 | 首版职责 |
|---|---|
| 程序／执行 agent | 按技术方案实现灰盒、配置入口、自测、逐次提交及 Windows 构建 |
| 策划 | 维护关卡配置，试玩并调整布局、血量及球参数，验证路线选择与失败压力 |
| 美术 1 | 探索方块、目标块及危险区域的识别方式 |
| 美术 2 | 探索球、发射器、界面和击碎反馈素材 |

灰盒闭环独立交付。程序维护场景和 Prefab，策划主要编辑关卡配置资产；共同文件顺序编辑，避免互相覆盖。

## 7. 产品验收与设计检查

设计依据是 **Core Loop 与 Game Feel**：闭环清晰、碰撞反馈及时，角度选择能影响本轮结果。体验目标为 MDA 中的感官反馈与挑战。

以下均为待实施和试玩验证的标准，不表示已经通过测试。

| 检查项 | 验收方式／风险处理 |
|---|---|
| 核心循环、Flow 与目标清晰 | 可从开局连续操作至胜负并重开；玩家知道目标、危险区域和当前阶段 |
| 自主性与熟练感 | 瞄准选择影响效果；玩家能够解释一次有效的角度选择；单人 MVP 的社交关联需求为 N/A |
| 物理直觉与适度夸张 | 球反弹方向和速度稳定；声画夸张不改变真实碰撞或遮蔽关键信息 |
| 信息、Gestalt 与认知负荷 | 同类方块表现一致；血量、目标和危险线一眼可辨；操作保持移动鼠标加单击 |
| 技巧、学习与复杂度 | 基础规则容易理解，能通过打缝和借墙反弹获得更好效果 |
| 约束、稀缺与风险收益 | 棋盘上移形成剩余空间压力；清理顶部急迫块与深入打出连弹构成取舍；召回放弃剩余伤害 |
| 正负反馈循环 | 球数固定，不存在成长失控；失败压力由可见方块上移形成 |
| 无主导策略 | 至少能演示直击紧急块和借反弹清侧面两种选择；若直射始终更优，先调整布局。当前尚无平衡结论 |
| 失败归因与结尾记忆 | 玩家能指出导致失败的越线块；目标击碎和胜利反馈形成清楚结束 |
| 前后期适用性 | 同一局前段和目标出现后的末段都可玩；长期成长和无限关卡扩展为本次 N/A |

最终必须能够演示钻缝、多次反弹和连续击碎；策划能独立修改关卡参数，并在 Windows 包中完成一局。
