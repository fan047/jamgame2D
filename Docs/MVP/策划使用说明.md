# 策划使用说明：试玩、调参与关卡验收

适用版本：2026-10-30 的 Holedown 类 Jam MVP 灰盒。

本文是操作与测试指南，不新增或修改产品规则。规则依据见 [产品设计](产品设计.md)，程序自测、构建信息和已知技术问题见 [交付说明](交付说明.md)。

## 一、先玩起来

### 不打开 Unity

解压 `Builds/HoledownMVP-Windows.zip`，运行其中的 `HoledownMVP/HoledownMVP.exe`。如果直接使用工程内构建目录，运行 `Builds/Windows/HoledownMVP.exe`。不要只复制 exe，旁边的运行时文件和文件夹必须一起保留。

### 在 Unity 中试玩和调参

1. 打开 `Assets/Scenes/SampleScene.unity`。
2. 点击 Play。
3. 鼠标移动瞄准，左键单击发射。发射方向在单击时锁定，后续移动鼠标不会改变本轮方向。
4. 飞行中可点击 `Recall`，立即结束剩余发射并回收活动球，已经造成的伤害保留。
5. 胜负后点击 `Restart`。重新测试修改后的配置时，建议先退出 Play，再重新进入。

鼠标必须在棋盘范围内、发射点下方；在发射点上方、场地外或按钮上不会发射。方向过于贴近水平时会限制到最大允许角度。

**参数和关卡请在退出 Play 后编辑。不要依赖 Play 中的临时修改保存结果。** 当前 Windows 包是构建时的配置快照；Unity 内修改配置不会自动更新旧运行包，验收新包需要重新构建。

## 二、试玩时需要知道的规则

- 球从上方固定位置向下发射，左右墙、底墙反弹，球与球不碰撞。
- 球向上越过顶部回收线时回收；本轮接受发射起超过 30 秒游戏时间会自动召回。
- 一次有效碰撞扣方块 1 血，血量归零立即移除碰撞与显示。
- 等待发射和活动球都清空后，才结算本轮；不是“最后一颗当前看见的球回收就立刻结算”。
- 本轮结算先检查目标是否击碎：是则获胜，不再上移；否则剩余块上移一格，并从底部补入下一条预设行。
- 推进后有块进入第 8 行及以上，判负。红线 y=8 是危险边界。
- 金色、带 `*` 标记的块是唯一目标，位于最后一条补行中。
- 清光普通块不提前获胜；补行耗尽后仍会继续上移。

### HUD 怎么看

| 显示 | 含义 |
|---|---|
| Round | 当前回合；瞄准阶段显示即将开始的回合 |
| Balls N (+M) | N 是当前活动球，M 是尚未发出的球 |
| Rows X/4 | 已补入的预设行数／预设补行总数；不是场上剩余行数 |
| Aiming | 可以瞄准发射 |
| Volley | 正在连发或飞行，可以召回 |
| Won / Lost | 本局结束，点击 Restart 重开 |

## 三、策划主要改这两个资产

在 Unity Project 面板中找到并选中下面的 `.asset`，在 Inspector 修改。**通常不需要改代码、场景、Prefab、碰撞层或相机。**

### 1. 球参数：GameSettings

位置：`Assets/Holedown/Data/GameSettings.asset`。

| Inspector 字段 | 默认值 | 调整时重点观察 |
|---|---:|---|
| Balls Per Round / ballsPerRound | 12 | 一轮可造成的总伤害、清场效率和回合时长 |
| Ball Radius / ballRadius | 0.12 | 可通过的通道宽度；图形、实际碰撞和预览随之变化 |
| Ball Speed / ballSpeed | 12 | 节奏、辨识度与高速碰撞稳定性 |
| Launch Interval / launchInterval | 0.08 秒 | 球串疏密、连发时间、早期召回的取舍 |
| Max Aim Angle / maxAimAngle | 75° | 相对正下方左右各自的最大角度，不是相对水平线 |
| Recall Timeout / recallTimeout | 30 秒 | 自动结束长时间飞行的兜底阈值 |

所有数值必须为有限正值；球数为正整数，球半径小于 0.5，最大角度小于 90°。通过校验只代表数据可运行，不代表玩法合理。

**注意球不是点：** 默认直径为 0.24，而相邻方块的标准间隙仅为 0.1，因此默认球不能穿过每一道看得见的小缝。设计“钻缝”路线时，要留真实能通过的空槽或缺口，并用瞄准预览与实射确认。

### 2. 关卡：DemoLevel

位置：`Assets/Holedown/Data/DemoLevel.asset`。

展开 `Initial Blocks` 编辑初始布局；展开 `Incoming Rows`，再展开每条行内的 `Blocks`，编辑补行顺序和内容。

| 字段 | 含义与限制 |
|---|---|
| column | 起始列，左侧为 0、右侧为 7；不是方块中心坐标 |
| row | 初始行，底部为 0、向上为 1–7；补行内所有块必须填 0 |
| width | 只能填 1 或 2；2 表示向右连续占两列 |
| health | 正整数，每次有效碰撞减 1 |
| target | 是否为目标块；全关卡只能有一个，且必须放在最后一条补行中 |

合法例子：`column=3, row=0, width=2, health=10, target=true`，表示底部第 0 行、占第 3 和第 4 列的 10 血目标。

常见错误：

- 起始列 7、宽度 2：越出右边界。
- 两个块占用了同一行同一列：重叠，即使起始列不同也不行。
- 将第一条补行的 row 填 1：补行一律从底部第 0 行进入，不用手填将来的高度。
- 在初始布局中放目标、放多个目标，或目标不在最后一条补行：初始化失败。
- 血量为 0、宽度为 3、初始行号为 8：非法数据。

初始化失败时，游戏会显示错误并禁止发射。先退出 Play，根据提示检查上述条件；不需要尝试用重开“跳过”错误。

### 棋盘位置速查

- 8 列，初始安全行 0–7；红色危险线 y=8。
- 发射点固定在 `(4,9)`，上方回收线 y=9.6。
- 单格尺寸为 0.9×0.9，双格尺寸为 1.9×0.9。
- `Incoming Rows` 的第一个列表元素是第一次补行，第二个是第二次，以此类推。
- 默认初始布局有 11 块、4 条补行；目标在第四次补行后才进入场地。

场地几何不是这两个资产中的可调参数。需要改列数、推进方向或危险线时，先与程序确认，不要只拖动场景里的线或墙。

## 四、推荐的调参方式

### 一次只回答一个问题

例如：“左侧是否有足够反弹空间？”“清理顶部块是否比继续深入更紧迫？”“召回是否真的要付出剩余伤害的代价？”

推荐流程：

1. 记下问题和当前配置版本／commit。
2. 只改一类变量，例如只改布局，或只改血量；不要同时改球速、球数和整关布局。
3. 退出并重新进入 Play，分别走直射和借墙路线。
4. 记录获胜／失败回合、召回次数、危险区域出现的时机，以及是否有明显卡球或错误预览。
5. 保留或撤回本轮改动，再开始下一个问题。不要用感觉模糊的“都调一点”替代对比。

### 当前最需要验证的问题

已确认默认关卡连续直射可在 5 轮获胜，说明闭环可运行，**不代表难度和策略深度达标**。优先比较：

- 直射中心是否几乎总是最优？借墙射击能否带来可解释的收益？
- 顶部危险块与底部高收益路线之间是否存在实际取舍？
- 目标进入后，玩家能否看懂目标、找到通路，而不是只能等待必输？
- 早召回能节约多少等待时间，又放弃了多少清块机会？

本文不预先指定新的血量或布局；具体修改结论以试玩记录和团队确认为准。

## 五、每次修改后的最低自测

| 检查项 | 通过条件 |
|---|---|
| 开局 | 无初始化错误，初始布局与编辑内容一致 |
| 三类射击 | 直射、斜射、借墙各试一次；预览与首次接触大致一致，没有穿墙／穿块／永久卡球 |
| 通道 | 预期的钻缝路线真实能通过，不只是视觉上有缝 |
| 发射中召回 | 点击 Recall 后不再生成后续球，保留伤害，棋盘只推进一次 |
| 补行 | 每轮按列表顺序加入底部，目标只出现一次 |
| 胜利 | 目标击碎后完成回收再显示 Victory；普通块清光不提前判胜 |
| 失败与重开 | 越线块能被指出；Defeat 原因明确；Restart 恢复原始配置，没有旧球 |
| 信息可读 | 数字、目标、危险线及按钮可辨，反馈不遮挡关键判断 |
| 方向选择 | 能演示并解释至少一次直击紧急块与一次借墙深入的价值 |

每次独立配置修改都遵守：**改动 → 自测 → 通过后一次 Git 提交 → 再开始下一项**。不会操作 Git 时，把准确资产路径、改动值和自测记录交给程序，由程序核对后提交；不要把失败项写成“通过”。不要提交 Library、日志或 Builds 目录。

关卡与球参数修改至少检查配置和实际试玩；影响碰撞稳定性、回合流程或初始化时，请程序补跑对应自动测试。重新构建和 Windows 包测试也由程序配合，不能用旧包的结果证明新配置通过。

报告 Bug 时额外补充：Unity 还是 Windows 包、球参数、发生前的回合和补行进度、能否稳定复现。碰到穿墙、提前推进、重复补行、目标已碎却判负等规则问题，先交给程序修复，不要靠改血量或布局掩盖。

## 七、与程序／美术协作

- 策划主要维护关卡和球参数；程序维护场景、Prefab、碰撞和构建。
- 同一配置资产顺序编辑，修改前确认没有别人同时在改；保留 `.meta`，不要通过删除重建来“重置”资产。
- 若美术反馈需要改变碰撞外形、方块尺寸或球半径，先明确是纯视觉修改还是规则修改。
- 策划最终需要给出的是：钻缝、多次反弹、连续击碎是否有趣，目标和失败压力是否清楚，是否有合理的路线选择；不能只用“自动测试通过”代替体验结论。
