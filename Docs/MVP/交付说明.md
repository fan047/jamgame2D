## 1. 运行与交付

- Unity：6000.4.3f1，打开 `Assets/Scenes/SampleScene.unity` 后 Play。
- Windows：运行 `Builds/Windows/HoledownMVP.exe`，必须保留同目录 DLL、Data、MonoBleedingEdge 等运行时文件，不能只拷贝 exe。
- 可分发压缩包：`Builds/HoledownMVP-Windows.zip`；解压后运行 `HoledownMVP/HoledownMVP.exe`。
- 默认窗口：720×1280、可调整尺寸、Windows x64、Mono。
- 操作：鼠标移动瞄准，左键单击发射；`Recall` 取消待发球并回收活动球；胜负后点击 `Restart`。
- HUD：Round 为当前／即将开始的回合；Balls 为活动球数量，括号内为待发射数；Rows 为补行进度。
- 重新构建：Edit Mode 中执行菜单 **Holedown > Build Windows MVP**，输出至上述 Windows 目录。脚本会临时为构建子进程指定项目内可写 TEMP/TMP，完成后恢复原值，不修改系统环境变量。

构建产物与本地测试日志不提交 Git。最终包对应玩法修复提交 `6419afc`，构建入口提交 `fe06ae8`；之后仅增加本交付说明。

## 2. Inspector 编辑入口

### 球参数

`Assets/Holedown/Data/GameSettings.asset`：

| 字段 | 默认值 | 作用 |
|---|---:|---|
| ballsPerRound | 12 | 每轮球数 |
| ballRadius | 0.12 | 实际碰撞半径，同时影响图形直径和瞄准预览 |
| ballSpeed | 12 | 世界单位／秒 |
| launchInterval | 0.08 | 连发间隔，秒 |
| maxAimAngle | 75 | 相对正下方的最大夹角，度 |
| recallTimeout | 30 | 游戏时间自动召回阈值，秒 |

在 Edit Mode 调整，重新 Play 验证；不要把 Play Mode 临时实验当成永久配置。数值必须为有限正值，半径小于 0.5，夹角小于 90°；仍需自行保证球能通过所设计的通道。

### 关卡

`Assets/Holedown/Data/DemoLevel.asset`：

- `initialBlocks`：初始块，编辑 column、row、width、health、target。
- `incomingRows`：有序补行列表，内部 `blocks` 的 row 必须为 0。
- 列号 0–7，初始行号 0–7，宽度只能为 1 或 2，不得重叠或超出 8 列，血量大于 0。
- 唯一目标必须位于最后一条补行；初始块不允许是目标。
- 开局会复制定义。运行时伤害和推进不写回配置；非法配置会显示初始化失败并禁止发射。

场地固定为文档约定的 8 列、8 个安全行；危险线 y=8、发射点 (4,9)、向上回收线 y=9.6。场景及 Prefab 由程序维护，策划主要编辑配置资产。

## 5. 已知限制与未完成的体验验收

1. 默认布局已确认连续直射可在 5 轮获胜。它是可运行起点，不代表已满足“没有主导策略”或达到理想难度；未擅自改变产品文档的默认关卡。需要策划实玩比较直击顶部急迫块与借墙深入路线，再独立调参、自测、提交。

3. 不是穷举物理测试；更极端参数、布局和分辨率需重跑受影响测试与试玩。
4. 本机 `D:/Temp/29742` 权限导致 Burst 首次链接失败，构建菜单已绕过；独立 Player 仍记录非阻塞的 D3D12 info queue 查询／PSO 缓存写入提示，退出时有 ComputeBuffer 清理提示。未观察到玩法中断，尚未进一步定位退出清理提示的来源。不宣称 Player 日志完全无提示。
5. 并未在另一台电脑做独立包兼容性测试。

建议试玩：先用直射路线验证完整小局；重开后尝试左右约 30–70° 的借墙射击，观察多次反弹、连续击碎和顶部压力；分别在连发早期／飞行末期召回，确认伤害保留且只上移一次。
