# 九关扩展与策划工具方案

日期为 2026-11-05。产品规则已经确认，本文供接手 agent 实施。正式 UI 的流程和素材仍按开放简报交由美术探索。 [UI 美术开放简报](UI美术制作清单.md)

**每次完成一项独立改动，先做对应自测。通过后提交一次 Git，再开始下一项。** 适用于规则、工具、场景、配置和文档。

## 1. 正式流程

- 正式配置包含九关，玩家从第 1 关依次打到第 9 关。击碎目标并完成本轮结算后进入关卡结果，第 9 关通关显示整趟完成。
- 第 1–3 关沿用现有背景，第 4–6 关和第 7–9 关各用一张新背景。三张图沿用水晶玻璃主题与当前棋盘安全区。方块先复用，新皮肤由美术按余量补充。
- 正式入关球数等于全局基础球数加已通关各关的实际奖励。换背景组时继续累计。本关击碎的奖励在过关后确认，下一关起生效。失败重试保留入关球数并清空本次待确认奖励。
- 非最终关的奖励块数量由合法布局决定。每块可填写任意合法正整数奖励，`+3`、`+5`、`+8`、`+10` 是快捷填值。最终关沿用无奖励块规则。目标块与奖励块互斥。

以基础 12 球、第一关四块奖励 `+3`、`+5`、`+8`、`+11` 为例。全拿时第二关每轮 39 球，只拿 `+5` 和 `+11` 时第二关每轮 28 球。第一关每轮都用入关的 12 球。

## 2. 策划工具

### 2.1 关卡管理

- 支持新增、复制、删除和重排关卡，编辑关名。新增与复制分配唯一 ID，复制保留初始布局、补行、血量和奖励。关名修改、重排与布局编辑保留现有 ID。
- 保留当前选择对应的关卡 ID。若删除当前关，选择临近关卡。新增未完成关和重排后出现的最终关奖励冲突可以在编辑器中修正，导出前定位到具体关卡和字段。
- 关卡管理与批量编辑纳入现有撤销／重做。每项操作一次撤销。切换关卡、批量应用或导出之前先处理待提交输入。

### 2.2 数值编辑

- 球参数继续在全局区编辑，包含基础球数、半径、速度、发射间隔、瞄准角度和自动召回时间。关卡区允许自由编辑合法的血量、加球值及现有布局字段。
- 对当前布局所选方块的血量或加球值支持批量设值、加减、乘倍率。应用前预览结果，倍率结果四舍五入为整数。`rewardBalls = 0` 表示普通块，合法正值使非目标块成为奖励块。
- 整批数值应用前检查所选方块的结果。血量必须为正整数，奖励必须为非负整数。越界或与目标身份冲突时显示对应方块和字段。保留普通块、奖励块、目标块的选择范围控制。
- 工具对配置失效条件报错，包含字段格式、整数范围、合法占格、唯一目标、最终关奖励和累计溢出。保留现有棋盘、形状与球参数的合法域。难度、奖励总额和连发时长的分析作为提示，由策划决定参数与导出。

### 2.3 预估与导出

- 每关显示本关奖励总量，以及最低入关球数和拿满前关奖励后的入关球数。最低值取基础球数，满奖励值取基础球数加此前所有奖励块的和。区间两端分别标识其含义。
- 提示名义最后一球发出的时间。按首球立即发出估算，`最后一球时间 = (每轮球数 - 1) × 发射间隔`。名义时间达到或超过自动召回时间时提示可能发不完，并允许导出。实际出球受帧率影响，提示用于调参。
- 继续导出 `settings.json` 与 `level.json`，与游戏配套发放工具。新工具可以导入已有单关和三关文件。用版本标识区分策划修订，替换后在游戏中核对已加载版本。

## 3. 策划测试模式

建议用同一个 Windows Player 的显式启动参数 `--planner-test` 进入测试模式，随包提供 `策划测试.cmd`。测试控件使用简单的选关与球数面板，正式启动继续走现有开始入口。这个启动形式是实现约定，可由接手 agent 按包内操作验证调整。

策划可选任意有效关卡，从该关初始布局开始。入关球数提供三种方式。

| 方式 | 计算与重载行为 |
|---|---|
| 无前关奖励，默认 | 用当前配置的全局基础球数。重载后按新基础值计算 |
| 拿满前关奖励 | 用全局基础球数加当前关之前全部奖励块的和。重载后按新的关序和配置重算 |
| 手填 | 用策划输入的合法正整数。重载保留该手填值 |

- 测试暂停菜单提供重载当前关。读取并校验两份文件，按稳定关卡 ID 重新定位，重建该关初始布局与尝试状态。前关奖励方式沿用上表。
- 若配置无效、文件缺失或被测关 ID 已删除，显示文件、字段或 ID 错误，保留旧快照和当前测试尝试，方便修正后再重载。改顺序时按 ID 找回同一关。
- 进入或重载成功时清理旧球、旧尝试回调和输入手势。测试通关显示本关结果，可以重测本关或返回选关。测试使用真实关序和关卡总数，因此第 7 关仍按非最终关判定奖励与目标。
- 手填球数只覆盖测试尝试的发射与显示数据。正式流程仍按实际击碎并结算的奖励推进。正式模式的配置重载从第 1 关重开。

## 4. 技术方案

### 4.1 配置与奖励规则

- 沿用 `settings.json` v1 和 `level.json` v2 的字段形状，继续读取旧 v1 关卡。新构建扩展 `rewardBalls` 的取值域。发包文档注明自定义奖励与多奖励块配置需搭配新版运行时。 [配置读取](../../Assets/Holedown/Scripts/Runtime/ExternalConfiguration.cs)
- 规则层由 `BoardState` 校验占格、目标和奖励值，`StageDefinition` 计算本关奖励总量，`CampaignDefinition` 校验最终关及跨关累计范围。分关求和与全程求和先用宽整数检查，再写入现有 `int` 字段，覆盖单关合计和基础球数加前关奖励两处溢出。 [棋盘规则](../../Assets/Holedown/Scripts/Rules/BoardState.cs) [关卡定义](../../Assets/Holedown/Scripts/Rules/CampaignDefinition.cs)
- `CampaignState.RecordHit` 接受合法正奖励，并沿用击碎条件、块 ID 去重、通关确认与失败重置。奖励显示、飘字和结算使用真实整数值，检查多位数文本。 [成长状态](../../Assets/Holedown/Scripts/Rules/CampaignState.cs)
- 浏览器与 C# 使用相同的合法域、溢出阈值和最终关判断。浏览器将 `entryOptions` 中取单块最大值的做法换成前关奖励求和，预估只展示最低和满奖两个边界。现有球参数与配置版本校验继续适用。 [编辑器校验](../../Tools/PlannerEditor/config-model.js)

### 4.2 工具与测试接入

- 工具复用 `EditorState.perform` 的数据副本和历史栈，统一处理关卡增删、排序和批量改值。界面负责选项与错误定位，模型负责可导出的数据是否合法。区分正在编辑的草稿与已导出版本。 [编辑器状态](../../Tools/PlannerEditor/editor-state.js)
- 在 `GameFlowController` 的现有配置读取与 `BeginAttempt` 路径接入测试上下文。保存关卡 ID、入关球数方式和手填值，发射与 HUD 共用一个本关生效球数。手填值与正式基础球数、待确认奖励分别保存。 [游戏流程](../../Assets/Holedown/Scripts/Runtime/GameFlowController.cs)
- 测试重载先准备候选 `LoadedConfiguration`，验证外置文件齐全、关卡 ID 存在及球数可用。通过后才切换快照并重建尝试。候选失败时释放候选资源，保留现有暂停局面。正式流程沿用现有重载入口。
- 工具继续使用浏览器下载及手动替换 JSON 的方式。Windows 构建入口将新工具、测试启动脚本和用法一起放进新编号目录。 [Windows 构建入口](../../Assets/Holedown/Scripts/Editor/WindowsBuild.cs)

### 4.3 背景切换

- 用 `VisualTheme` 保存三组背景引用，`SceneVisuals` 在进入关卡时按当前关序选图。第 1–3、4–6、7–9 关分别对应三组。缺图或超出区间时用现有主题背景。
- 背景映射随 Unity 主题资产发布。关卡 JSON 继续描述玩法数据。当前舞台尺寸、金环、相机安全区和碰撞体以构建 05 为基线。 [主题资产代码](../../Assets/Holedown/Scripts/Runtime/VisualTheme.cs) [场景显示](../../Assets/Holedown/Scripts/Runtime/SceneVisuals.cs)

## 5. 基线、实施顺序与交付

策划前三关的最近已核对版本在本机构建 05 的 `Builds/05/Windows/Config`。该目录包含试玩后的策划布局，工程根目录的 `Config` 仍是旧样例，两处关卡版本文字均为 `growth-1`。接手时以策划确认的最新文件合并，记录来源及哈希，第三关的难度修订由策划提供。

| 基线文件 | 2026-11-05 核对的 SHA-256 |
|---|---|
| 构建 05 的 `settings.json` | `EB9985A8BC10EAAA8FBA0B94FAC02AD45597C91B18CE9C720E4B7A2A4D2C8697` |
| 构建 05 的 `level.json` | `E933847965CE541A5368F4FC8FB90DD60E96E8D5AB0EA74C9B03BC82CF84E028` |

每批按表完成对应自测并提交，再进入下一批。进一步拆分时，每个独立改动也执行同一闭环。

| 顺序 | 独立改动 | 自测通过条件 |
|---|---|---|
| 1 | 自定义奖励端到端 | 旧配置可读。四块及以上、超过 `+10`、多块实际击碎、失败重试、最终关与累计溢出在工具和运行时结果一致 |
| 2 | 关卡管理 | 工具可从三关扩到九关，复制数据完整且 ID 唯一。重排、删除、撤销／重做后能正确定位。把含奖励的关移到末尾时定位到错误 |
| 3 | 数值批量操作与预估 | 血量和奖励的设值、加减、倍率均可预览和一次撤销。无效批量修改保持原值。满奖预估加总所有奖励，发射时间提示可见且合法数据可导出 |
| 4 | 测试模式与当前关重载 | Windows Player 可直达第 7 关，三种球数方式分别复核。修改文件后回同一关初始布局。重排后按 ID 恢复，损坏或缺失文件时保留旧局，修复后可重载 |
| 5 | 三组背景 | 正式切关、测试直达和重载时图组正确。验证第 3→4 与第 6→7 关、未绑定回退和竖横屏对齐 |
| 6 | 九关配置与新构建 | 使用策划确认的九关配置与两张新背景制作新编号包。普通启动可从 1 连到 9 并结算成长，最终关显示整趟完成。策划测试启动和配套工具可用 |

验证优先复用现有规则、配置、浏览器和 Player 测试入口。实际试玩要区分目标块通关、奖励路线、数值压力与画面检查。记录构建号、配置版本、关卡 ID、入关球数与测试结果。构建 05 的历史证据与本轮执行记录分开。 [构建 05 交付说明](正式美术样片交付说明.md)
