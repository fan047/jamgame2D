## 已实现

1. 奖励块允许任意正 Int32 奖励，同关可有多个；目标与奖励互斥，最终关不能有奖励。单关合计和全程累计先用宽整数检查溢出。奖励仅在实际击碎后登记、按块去重、通关后确认，失败重试清空待确认奖励。
2. 工具支持关卡新增、完整复制、删除、重排、改名；已有 ID 稳定，复制分配唯一 ID。支持撤销／重做及不完整草稿，导出前定位错误。
3. 血量和奖励支持批量设值、加减、乘倍率、四舍五入与应用前预览；整批校验、原子应用、一次撤销。提供普通／奖励／目标选择范围、最低／满奖入关球数及名义末球发射时间提示。
4. 显式策划测试模式可指定任意有效关卡，支持基础球数、前关奖励全拿、手填三种方式。HUD 和真实发射共用有效球数。通关可重测或返回选择，不推进正式战役。
5. 测试模式重载按稳定关卡 ID 定位；先读取校验候选，再切换快照与清理旧球。文件损坏、缺失或 ID 删除时保留旧配置、尝试及暂停状态。手填值保留，其他方式重新计算。普通模式重载仍从第一关重开。
6. `VisualTheme` 新增三组背景引用：`backgroundStages1To3`、`backgroundStages4To6`、`backgroundStages7To9`。进入关卡／重载的流程变化会触发选择；未绑定及超出九关范围回退 `background`。目前新槽位未绑定，沿用既有背景。舞台尺寸、金环和碰撞体未改。
7. 方块血量／奖励文本随形状自适应，完整 Int32 数值不跨出方块文本区域。正式 UI 流程与素材仍待美术设计，测试面板为英文简易控件，不代表最终 UI。

工程根目录 `Config/level.json` 和工具默认值已同步文档指定的构建 05 策划修订，不再发布旧样例布局。08 随包两份文件与 05 原文件逐字节哈希一致：

| 文件 | SHA-256 |
|---|---|
| settings.json | `EB9985A8BC10EAAA8FBA0B94FAC02AD45597C91B18CE9C720E4B7A2A4D2C8697` |

两份版本文字仍分别为 `demo-1`、`growth-1`，不能只凭版本文字判断新旧。后续策划修订应使用可区分的新版本标识。配置依旧为 settings v1、level v2，并兼容旧 level v1；多奖励块与自定义奖励必须搭配新版运行时，不能拿新 JSON 配旧 exe。

工具导出只生成玩法 JSON，不包含主题图片。请把两份 JSON 放到**实际运行 exe 同目录的 Config**，不要误改另一个旧包。美术由完整运行目录内的 Unity 资源发布；不要仅复制 exe 或把旧程序与新 Data 文件夹混用。

## 策划验收步骤

1. 完整解压新包，不与旧包混放。普通启动核对 `growth-1` 三关及现有主题。
2. 打开配套工具，导入自己最新两份 JSON，复制／新增关卡到九关，修正布局、最终关奖励冲突和关卡名称；改动后先预览批量操作，再导出。
3. 关闭游戏或暂停后备份 Config，再替换两份 JSON。普通模式用 Reload + Restart 重开第一关。
4. 用 `策划测试.cmd` 启动，选真实第七关，分别试基础／满前关／手填模式，核对 HUD。编辑顺序后重载应保留同一 ID，而非相同序号。
5. 测试中损坏一份 JSON 后点重载，确认旧局保留；修复后再次重载。不要只关闭错误提示而继续假设已加载新文件。
6. 正式九关和新背景交齐后，再验收完整九关难度、实际奖励路线、两处分组换图及最终整趟完成。当前自动夹具不替代该验收。
