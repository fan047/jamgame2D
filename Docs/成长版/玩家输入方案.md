# 玩家输入：产品规则与技术方案

日期：2026-11-02。状态：访谈已确认，供其他工程师或 agent 实施；本次只编写方案，不实现功能。

沿用 [成长版技术方案](技术方案.md) 的轻量分层、组件组合、有限状态机、局部事件与手动依赖注入。开始页和配置生命周期与 [美术接入技术方案](美术接入技术方案.md) 一起实施；输入、暂停及失焦行为以本文为准。

## 1. 已确认的操作

本轮面向 Windows 鼠标与键盘。保持移动鼠标瞄准、左键按下发射；补充空格召回、Esc／按钮暂停和失焦保护。整套流程可仅用鼠标完成。

| 动作 | 输入／界面 | 确定行为 |
|---|---|---|
| 瞄准 | 移动鼠标 | 仅瞄准阶段显示预览；指向有效棋盘区域 |
| 发射 | 鼠标左键按下边沿 | 一次按下只发射一轮；连发与飞行过程中锁定新发射 |
| 召回 | Space 按下边沿／现有 Recall 按钮 | 仅 Volley 有效，包含尚在连发和已经飞行的阶段；按住不重复触发 |
| 暂停 | Esc 按下边沿／HUD Pause 按钮 | 从有效游戏阶段进入暂停；Esc 只打开暂停，继续由 Continue 明确执行 |
| 自动暂停 | 应用失去焦点 | 保留本轮，返回后仍显示暂停，等待 Continue |
| 继续 | 暂停层 Continue 按钮 | 恢复同一次尝试、同一轮及剩余计时；此点击不发球 |
| 重载并重开 | 暂停层次级 Reload + Restart 按钮 | 读取文件，清空本趟成长，直接开始第 1 关；不经过开始页 |
| 开始／下一关／重试等 | 各自已有或计划按钮 | 每次点击只执行该按钮的一次动作；切换完成后发射须有新的左键按下 |

暂停层主操作为 Continue；Reload + Restart 使用次级视觉，文字说明“读取文件并从第 1 关重开”。HUD 保留 Recall，增加 Pause；这些使用程序 UI，无新增必需美术图片。提示应能读出“左键发射 · 空格召回 · Esc 暂停”。

Space 不兼任开始、发射、下一关或 UI 提交。保留当前 Enter 对选中 UI 按钮的标准 Submit 能力，统一经过按钮权限校验，不新增全局 Enter 快捷命令。重载使用显式按钮，不添加快捷键。本轮不扩展拖拽蓄力、手柄、触屏、按键重绑或输入缓存。

## 2. 瞄准与点击边界

- 沿用 Origin=(4,9)，鼠标需位于游戏相机 pixelRect 内，转换后满足 x∈[0,8]、y∈[0,9)。发射点本身和向上方向无效。
- 按 settings.maxAimAngle 夹紧相对于向下的夹角，默认 ±75°；预览和实际发射使用同一最终方向。
- 预览保持以真实球半径 CircleCast 到首次碰撞；本轮不新增多次反弹预测。
- 指针在 UI、窗口外、相机有效区域外或无效瞄准区时，隐藏预览且不接受发射。切换窗口和改变窗口尺寸后使用当前坐标及相机参数重新计算。
- 飞行期间的左键不保留到下一轮。任何时候按住左键，均不会在后来进入 Aiming 时自动发射。
- UI 在按下时占用的鼠标手势，直到抬起都归 UI；拖离按钮再抬起不会变成发射。仅装饰图关闭 Raycast Target，所有可点击 UI 必须参与拦截。
- Start、Continue、NextStage、RetryStage、RestartRun、ReloadAndRestart 均消耗本次手势；新状态至少等待旧按键释放，随后新的按下才可发射。

## 3. 状态权限

运行层扩展 AppPhase 为 Loading、Title、Playing、Paused、ConfigError。GameSession 继续保持原 Initializing／Aiming／Volley／Recalling／Settling／Won／Lost；Paused 不写入规则层，不重建 Session。

| 当前上下文 | 发射／预览 | Recall／Space | Esc／HUD Pause | 可用 UI |
|---|---|---|---|---|
| Loading／Initializing／切换中 | 禁止 | 禁止 | 忽略 | 只显示状态，禁止重复命令 |
| Title | 禁止 | 禁止 | 忽略 | 最简 Start 入口 |
| Playing + Aiming | 允许有效瞄准和新按下 | 禁止 | 允许 | Pause 及现有重开／重载入口 |
| Playing + Volley | 禁止 | 允许一次 | 允许 | Recall、Pause 及现有重开／重载入口 |
| Playing + Recalling | 禁止 | 忽略重复请求 | 允许 | Pause 及现有重开／重载入口 |
| Settling | 禁止 | 禁止 | 同步结算完成后重新判断 | 不允许打断结算事务 |
| Paused | 禁止 | 禁止 | 不切回游戏 | Continue、Reload + Restart |
| Playing + Won／Lost | 禁止 | 禁止 | 忽略 | 对应的下一关／重试／重开／重载 |
| ConfigError | 禁止 | 禁止 | 忽略 | 错误信息、修正文件后的重载 |

无焦点时禁止全部用户命令，包括 UI；Title、结果页和错误页失焦只保护输入，不额外覆盖一层无意义的暂停菜单。结算是同步事务，若已结束至 Won／Lost，保留结果页；否则在返回可暂停的活动阶段后处理暂停请求。

同一输入更新内的有效请求按“失焦／暂停 → 显式 UI 命令 → 召回 → 发射”仲裁。暂停与发射或召回同时发生时，只暂停；同一手势只执行一个命令。不在后续帧补执行被丢弃的请求。

## 4. 失焦与恢复合同

### 4.1 失焦

活动关卡收到 OnApplicationFocus(false) 时立即关闭模拟与输入许可，清空待处理请求，隐藏预览，进入 Paused。不能等下一次常规 Update 才记录暂停，因为窗口后台可能停止更新。

保留 SessionId、VolleyId、球位置与速度、已发／未发／活动球计数、块血量、待结算奖励、连发等待和自动召回剩余时间。暂停不扣球、不召回、不结算、不推进棋盘。重复失焦或重复暂停不能覆盖第一次保存的恢复状态。

### 4.2 返回

- 用鼠标点击重新激活窗口：该次激活点击只激活窗口，即使指针就在 Continue 上，也不能继续或重载。释放后，再点击 Continue 才恢复。
- 用 Alt+Tab 返回：保持暂停；完成焦点恢复后，下一次新的 Continue 点击即可恢复，无需额外点击一次来“解锁”。
- 失焦前按住或返回时仍按住的左键、Space、Esc，不得在恢复、换图或切换 Action Map 时被解释成新按下。
- Continue 只在已聚焦且新的有效 UI 手势下执行；恢复后，发射与召回仍各自等待自己的释放和新按下。按住 Space 不应阻止新的鼠标发射。

实现使用焦点代次、输入更新边界与按下／释放序列。返回焦点的输入更新先隔离激活手势；在完整输入更新观察到左键松开且没有遗留按下后，才接受后续 UI 按下。不用固定等待若干秒作为判据，也不通过吞掉“返回后的第一次任意点击”实现，以免 Alt+Tab 后需要点两次。

焦点回调与鼠标事件顺序必须在实际 Windows Player 中验证，覆盖按下先到、焦点先到及按住拖回窗口；仅一个 hasFocus 布尔值或仅重置 EventSystem 不足以证明通过。若实际平台序列无法可靠区分，需补齐平台事件处理再交付，不能悄悄改变本节的操作合同。

## 6. 架构与设计模式

继续轻量分层。使用输入适配器、既有状态机和普通命令方法；通过 Inspector 引用与局部事件连接。无需全局事件总线、DI 容器、命令历史、独立输入框架或新规则层依赖。

| 对象 | 职责 |
|---|---|
| 新增 PlayerInputController（Runtime） | 读取命名 Action，管理自己拥有的玩法 Map，采集按下边沿；向流程提交带输入代次的意图 |
| 修改 AimInput | 给出当前指针的有效最终方向及预览；保留当前帧 UI Raycast；不自行改变游戏状态 |
| 修改 GameFlowController | 最终命令校验、输入代次、单帧仲裁、暂停所有权、焦点状态和配置生命周期；保持唯一流程权威 |
| 新增 PauseView，修改 HudView | 展示 Pause／Continue／Reload，提交同一组流程命令；不操作 Time.timeScale 或规则数据 |
| 修改 FeedbackPlayer | 暂停／恢复自己拥有的游戏音源；继续使用原有受击事件和清理机制 |
| Rules | 保持纯 C#；CampaignState、GameSession、BoardState 不依赖 InputSystem、UI 或 Unity 时间 |

上述新增 C# 均置于 Assets/Holedown/Scripts/Runtime；测试置于 Scripts/Tests 对应目录。类名可随现有风格微调，职责边界不变。

### 6.1 动作资产与所有权

在现有根动作资产中增加以下 Map，使用显式 InputActionReference／InputActionAsset 引用；本轮不再叠加 PlayerInput 消息分发路径。

| Map／Action | 类型／绑定 | 启用条件 |
|---|---|---|
| HoledownAim/Point | Value Vector2；<Mouse>/position | 聚焦、Playing + Aiming |
| HoledownAim/Fire | Button，按下；<Mouse>/leftButton | 同上，且经过释放门禁 |
| HoledownVolley/Recall | Button，按下；<Keyboard>/space | 聚焦、Playing + Volley |
| HoledownSystem/Pause | Button，按下；<Keyboard>/escape | 聚焦的可暂停游戏阶段 |
| UI | 保留 Point、Click、Submit、Navigate 等 UI 动作 | 有可操作界面；失焦和激活手势另有统一门禁 |

PlayerInputController 在初始化即关闭不适用的玩法 Map，只管理 Holedown*；InputSystemUIInputModule 管理 UI 动作。禁止每帧启用整个资产覆盖上下文禁用；解绑回调与关闭自有 Map 成对处理。项目级动作默认启用和手动启停的差别见 [Unity Actions](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/manual/Actions.html)。

将 UI 模块的 Cancel 引用解绑或接入同一暂停意图，Esc 只允许一个消费者，不能同时触发开关两次。保留 Enter Submit，不增加 Space Submit。开始、恢复和切关后清理旧选择／旧手势，避免选中按钮意外再次提交。

### 6.2 分发与最终校验

普通 Action 回调和 UI 回调采集意图，不直接无序改变关卡；统一在 GameFlowController.LateUpdate 的结算前分发。暂停／失焦采用高优先级同步入口，收到时立即关闭输入及模拟许可并取得暂停所有权，使本帧后续连发协程和超时逻辑也遵守暂停；其余意图随后丢弃。不能只在帧末暂停却允许其间再发一个球。

分发后仅 Playing 执行自动超时召回和原统一结算。将当前 Update 中的自动召回纳入这一许可范围；已完成的物理步／同步伤害事务保持有效，不回滚半笔伤害。

每条意图携带采集时的上下文代次；开始、切关、重试、重载、下一轮、暂停、恢复与焦点变化均使旧意图失效。每帧最多接受一个改变流程的用户命令。释放门禁按动作分别保存，不能以“任意键未松开”为由锁死所有操作。

GameFlow 的 TryFire／RequestRecall 等公开玩法命令仍校验 AppPhase、SessionPhase、焦点、暂停及切换帧；按钮命令校验对应页面与单次切换。输入代次与 UI 手势校验位于统一分发处，不能只通过隐藏按钮或 CanAim 保障正确。保留现有 SessionId／VolleyId 对旧球回调的拒绝。

当帧指针位置用 EventSystem.RaycastAll 判断 UI；原始 Action 回调里不要依赖 IsPointerOverGameObject 的上一帧 UI 结果。UI 与玩法默认都可能收到同一指针输入，需要显式仲裁。[Unity UI 输入歧义说明](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.19/manual/UISupport.html)

## 7. 暂停、计时与重载

### 7.1 暂停所有权

首次有效暂停保存当前 Time.timeScale，设置为 0；重复暂停不覆盖保存值。恢复精确还原原值，包括测试中的 20 倍速；不能硬编码恢复为 1。本轮不修改 fixedDeltaTime。

timeScale=0 会停止后续 FixedUpdate 与等待中的 WaitForSeconds；Update／LateUpdate 仍需显式流程门禁。[Unity Time.timeScale](https://docs.unity3d.com/6000.4/Documentation/ScriptReference/Time-timeScale.html)

- 保留现有使用缩放游戏时间的连发间隔、Time.time 自动召回与受击／碎片时序。恢复后继续剩余等待，不补算后台真实经过的时间。
- 连发协程在注册新球前检查模拟许可；暂停时等待恢复，不能结束协程、重建轮次或跳过未发球。处理等待恰好完成与暂停同帧的情况。
- 暂停时禁止 TryBeginSettlement／Settle 和自动召回，即使 Pending=0、Active=0 也不推进一行。恢复后按原结算入口执行一次。
- 不通过禁用 GameFlowController／游戏根节点暂停：当前 OnDisable 会 ClearAttempt 并销毁球。
- 音源使用 Pause／UnPause 保留播放位置，只恢复本模块实际暂停的音源；重载／退出时释放相应所有权。暂停菜单动画若需要，使用 unscaled 时间；UI 输入继续可用。
- 退出 Play Mode、禁用、销毁、重新加载与失败路径均释放自己持有的时间／音频暂停，避免污染后续场景和测试。终止尝试仍走既有 ClearAttempt，继续游戏不走 ClearAttempt。

### 7.2 暂停层 Reload + Restart

复用美术方案约定的“当前场景内重读配置”。该按钮是明确放弃当前尝试并读取文件的动作，不等于 Continue 或使用旧快照的 RestartRun。

流程：消耗本次 UI 手势 → 进入 Loading 并锁输入 → 清理旧尝试 → 释放自有暂停时间／音源状态 → 释放旧配置 → 读取并校验文件 → 创建新 CampaignState → 直接 BeginAttempt 第 1 关。不能先恢复旧球一帧再销毁，不能残留全局 timeScale=0。

读取失败进入 ConfigError，显示错误与重载入口，保持 UI 可响应，不混用旧配置。记录“已经开始过游戏”的重载意图，修正文件再重载后仍直接进入第 1 关；只有从未开始的 Title／启动错误修复后回 Title。Restart() 兼容别名继续指向完整配置重载。

### 自动验证的必要场景

1. Aiming 有效新按下发射一次；按住不追加；Volley 内点击不缓存；回到 Aiming 后须释放再按。预览与最终发射向量一致。
2. UI 上按下／拖出释放、相机外点击、窗口外点击不发球；首次 Start、Continue、NextStage、RetryStage、RestartRun 和 Reload 点击不穿透成发射。
3. Space 仅 Volley 召回一次，取消未发球并按原逻辑回收；Title、Aiming、Recalling、Paused、结果页均不触发其他动作。
4. Esc 长按只暂停一次；同帧 Esc + Fire／Recall 只暂停；UI Cancel 不再次关闭暂停；单纯 Esc 不执行 Continue。
5. 暂停中固定球位置／速度与计数、块血量及奖励不变；连发等待与自动召回保留剩余时间；恢复不补发积压帧；Pending=0、Active=0 时不提前结算。
6. 同一暂停重复请求不覆盖原 timeScale；以 1 与 20 两种原值验证恢复；暂停中重载成功／失败、组件退出后都没有时间或音频所有权泄漏。
7. 旧代次请求和旧球回调无效；恢复时分别按住左键、Space、Esc，验证各自释放门禁；Space 持有期间不影响新的合法左键。

规则和流程测试之外，加入真实 Mouse／Keyboard 状态事件的集成测试（例如 Input System 测试设备与事件队列）；不能仅直接调用 TryFire 或 ExecuteEvents 就声称覆盖了物理按键、按住和焦点顺序。测试可显式调用 StartGame 建立场景，不得关闭正式门禁来迁就旧测试。

### Windows Player 手动验收

- 分别在 Aiming、连发中、飞行中 Alt+Tab 离开，等待超过 recallTimeout 后返回；保持暂停，点一次新的 Continue 恢复原轮，无时间跳过。
- 点击窗口棋盘、Continue、Reload 所在位置重新激活，均只激活；抬起后新的按钮点击才执行。覆盖最小化恢复、按住拖回及焦点回调／鼠标事件的实际顺序。
- 左键按住跨越切关／恢复／下轮、Space 按住跨回收／下轮、Esc 长按；均无重复或跨状态误触。
- 分别点击 Start／Continue／Next／Retry，验证一次手势只切换一次且不发球；切换中的重复 UI 命令无效，切换后新的有效棋盘按下才可发射。测试同一帧暂停与发射／召回。
- 鼠标独立完成开始、发射、Recall、Pause、Continue、重载和结果页操作；Enter 选中按钮提交仍受同样权限限制。
- 在 540×960 或 720×1280 与 1280×720，以及运行中缩放窗口后检查 UI 命中区、瞄准和边界。
- 保留原真实物理、成长、重试、配置重载与生命周期回归；记录自动测试结果、实际操作结果、构建编号和对应 Git commit。只通过 Editor 测试不能代替 Player 失焦验收。
