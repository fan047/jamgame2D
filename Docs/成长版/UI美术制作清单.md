# UI 美术制作清单

日期：2026-11-04。状态：范围与方向已确认，供两位美术制作及程序占位使用。本轮交付清单，不制作正式 UI 图片、不修改场景或实现 UI。

排版参考见 [五页中文 UI 占位样例](UI样例/UI占位样例.png)，来源与示意边界见 [生成记录](UI样例/生成记录.md)。该预览用于说明布局与共用关系，正式 UI 图片仍由美术按下表提供。

## 1. 给美术的制作目标

为现有矿洞像素风游戏制作一套共用 UI，覆盖游戏 HUD、开始页、暂停页、结算页和配置错误页。程序先完成中文占位布局，正式资源由美术提供后替换。

- 视觉沿用已有深蓝矿洞、灰蓝岩石和水晶；面板用深蓝底、薄岩石边框，主按钮为金色，次按钮为灰蓝色。
- 青水晶与橙箭头继续表达游戏中的目标和加球奖励，菜单主要按钮使用金色层级。
- 文字使用清晰的中文字体，数值与操作名称由程序绘制。面板、按钮、图标交独立素材，保留干净的文字区域。
- 竖版 9:16 构图，横屏完整显示中央舞台并在左右留边。请在现有矿洞背景上制作排版预览，留出中央棋盘和球路。
- **交付 9 张共用 PNG：基础 7 张先交，结算徽记 2 张随后补齐。** 全部页面复用这些素材，不需要每页单独制作一套按钮和窗口。

当前游戏素材与实现基线见 [构建 05 交付说明](正式美术样片交付说明.md)，总体视觉见 [VISUAL_DESIGN.md](../../VISUAL_DESIGN.md)。本轮 UI 资源按本清单由美术制作，程序使用占位图等待回交；此前游戏素材的 agent 转换／补图流程不自动扩展到这批 UI。

九宫格指边角保持大小、中间和边条可以延展。交付一张完整底图，并在说明或示意图中标出左／右／上／下切分像素；不要切成九个文件。小按钮与大窗口延展后，边角不变形、边框粗细一致。

图标和徽记主体居中，四周透明留边小而一致。按钮中央的高光、纹理和装饰不能降低中文文字对比；面板中心避免密集裂痕和亮斑。图标在实际小尺寸下检查，不能依赖大图细节才能识别。

## 3. 五类页面如何复用

排版预览可使用 1080×1920 竖版画布；横屏再附一张中央舞台完整显示的示意。预览中的中文和数字作为布局参考，最终导出的底图保持无字。

| 页面 | 美术需要排出的元素 | 共用 PNG／现有素材 | 程序文字与按钮示例 |
|---|---|---|---|
| 游戏 HUD | 顶部信息区、暂停入口、召回入口；中央留给球路 | HUD 横条、暂停／召回图标、次按钮；球／目标／奖励图可复用现有素材 | 第 1/3 关、每轮 12 球、第 1 回合、下关奖励 +3、召回（Space） |
| 开始页 | 标题文字区、已有无字矿洞主视觉、一个主要开始按钮 | 现有背景与 title_logo.png、主按钮 | 游戏标题、开始游戏、简短操作提示 |
| 暂停页 | 标题、简短说明、主次两个操作，层级清楚 | 共用窗口、主按钮、次按钮；重载按钮可带回转箭头 | 已暂停、继续游戏、重载配置并重开；说明“读取文件并从第 1 关重开” |
| 结算页 | 通关／整趟完成／失败三种文字版式，徽记与主次操作 | 共用窗口、成功／失败徽记、主次按钮 | 本关通关＋下一关；全部通关＋再玩一次；本关失败＋重试本关；次按钮“从第一关重开” |
| 配置错误页 | 错误标题、可换行的说明区、重新加载按钮 | 共用窗口、主按钮；沿用正常文字与按钮体系 | 配置加载失败、具体文件／字段／原因、重新加载 |

以上是排版和素材需求，具体展示数值由程序提供。配置错误的说明区应容纳多行中文、英文路径或字段，不靠把字体缩到很小来塞进固定高度。单关通关与全部通关共用成功徽记，不另画两套结算窗口。

请交付五类页面的排版预览；结算页在同一预览文件中标注三种状态即可。预览可以是源文件里的画板或导出的 JPG／PNG，**它们用于说明布局，不作为游戏整屏贴图**，不计入 9 张正式 PNG。

## 4. 文字、字体和交互状态的分工

### 字体使用现有资源

字体来自用户提供的 D:/Downloads/unity/Font，先使用同一家族的静态 TTF：

| 用途 | 字体文件 |
|---|---|
| 正文、说明、错误信息 | D:/Downloads/unity/Font/static/NotoSansSC-Regular.ttf |
| HUD 数字、按钮文字 | D:/Downloads/unity/Font/static/NotoSansSC-Medium.ttf |
| 页面标题 | D:/Downloads/unity/Font/static/NotoSansSC-SemiBold.ttf |

已只读核对这三类字体的简体中文样本文案、常用标点和数字覆盖；尚未在 Unity 中导入或进行小字号实屏验收。该字体目录有 README.txt 与 OFL.txt，程序引入字体时一并保留对应说明。

字体／TMP 字表由程序接入，美术使用相同字体做排版预览即可，不增加手绘中文字库任务。页面文字、按钮名称、关卡序号、球数、血量和 +3／+5 均保持程序文本。正式游戏名确定后，另行安排带字标题标志；本轮先复用已有无字主视觉和程序标题。

### 按钮先交常态，程序负责交互变化

| 状态／效果 | 本轮处理方式 |
|---|---|
| 常态 | 使用主／次按钮各自的 PNG |
| 鼠标悬停、键盘选中 | 程序提高亮度或加细描边；美术可在预览中标注色值 |
| 按下 | 程序轻微压缩／下移或调暗，边框形状保持稳定 |
| 禁用 | 程序降低亮度与饱和度，保留可读文字 |
| 暂停／结算背景压暗 | 程序使用单色半透明遮罩 |
| 文字出现、按钮反馈、短过渡 | 程序动画 |

因此当前清单只需要两个按钮常态底图，不额外要求四态 × 多种文字的图片。美术若希望某种状态具有专门造型，可作为后续增补项提出，先完成基础交付。

## 6. 文件交付和检查

- 交付包含：9 张独立 PNG、可编辑源文件、九宫格切分标注、五类页面排版预览；命名按本清单。
- PNG 保留真实透明通道，避免把深色展示底、文字、选框或透明棋盘格烘焙进去。面板中心可以有深蓝底色和半透明度，四角与图标外部保持透明。
- 同一套素材的像素颗粒、边框和左上光照一致；横条与按钮可拉长，方形图标可套用共用按钮底。
- 在浅／深两种底色上检查透明边缘，再放到真实矿洞背景检查文字区域、图标和主次层级。
- 程序在 540×960 或 720×1280、1280×720 检查真实尺寸、中文缺字、九宫格、按钮状态和窗口缩放；预览排版不能替代实际运行检查。
- 正式 UI 素材建议落位 Assets/Holedown/Art/UI；字体由程序放入自己的字体目录。原始交付与源文件由团队保留。

建议两位美术分工：美术 A 负责两种面板与两种按钮，共 4 张；美术 B 负责 3 个操作图标与 2 个结算徽记，共 5 张；共同完成排版预览与风格统一。

## 7. 程序占位与回交接入

程序先用可替换的简单色块、图标和中文文本验证五页布局；本轮不提前生成一套正式 UI 图。美术按 A 批 7 张基础素材先交，程序完成试装后再补 B 批结算徽记。

现有操作语义和 [输入合同](玩家输入方案.md) 继续适用：Continue 恢复原轮，Reload 读取配置并从第 1 关重开；Space 只召回，Esc 只暂停；按钮手势不穿透发射，失焦返回的激活点击只负责激活。菜单视觉变化不能改变这些行为。

**程序侧每次独立改动 → 对应自测 → 通过后一次 Git 提交。** 本文只交付 UI 美术任务单；占位 UI、中文字体导入和正式素材接入另由执行 agent 完成，本次未实施或运行相应测试。
