# 水晶矿洞 · 中期版技术方案与验收

## 架构与配置

沿用 Unity 工程的规则、运行时与表现分层。`GameSession` 是单关尝试状态机，`BoardState` 管占格、伤害和推进，`CampaignState` 管跨关奖励，`GameFlowController` 管尝试和输入生命周期。`LoadedConfiguration` 提供读取后的配置快照，每次重试或切关新建棋盘。`FeedbackPlayer`、HUD 和场景表现通过既有事件观察已生效的结果。球回调按会话、发射轮次和活动球身份校验，通关确认和切关只接受一次有效操作。

| 文件 | 约定 |
|---|---|
| `settings.json` | `schemaVersion=1`，全局基础球数、半径、速度、发射间隔、瞄准角度和自动召回时间。 |
| `level.json` | `schemaVersion=2`，有序关卡列表，每关用唯一稳定 ID。改名与重排保留 ID，新增与复制分配新 ID。兼容读取旧单关 v1，工作台导出 v2。 |
| `audio.json` | 中期版新增可选配置。独立于球参和关卡校验，版本和协议见下节。 |

球参与关卡成对读取。正常启动两份都缺失时使用内置回退，只缺一份或非法时提示错误。正式模式「重载并重开」读取磁盘并从第 1 关重开，「重新开始全程」使用已载入快照。策划模式的关卡重载先验证文件、ID 与有效球数，再替换快照并重建本关。失败保留原局。基础和满前奖模式按新配置重算，手填模式保留手填值。

初始块 `row`、`column` 为 `0–7`，初始图顶部为 `row 7`。补行使用局部 `row=0`、`height=1`。工作台和 C# 都校验重叠、越界、唯一目标、最终关奖励及累计溢出。批量改值只作用于当前布局组选中项，预览后原子应用，可一次撤销。普通改值保留滚动和选中位置。跨组、跳转和导出前处理未应用的属性草稿。

`VisualTheme` 与 `SceneVisuals` 按当前关序映射 1–3、4–6、7–9 的背景。未绑定或超出分组时回退现有主题图。背景完整等比显示，金环独立对齐 `(4,9)`，舞台与装饰由表现层处理。场地、危险线与碰撞继续使用现有坐标。

## 占位 UI 与验证

本轮按[占位 UI 方案](占位UI方案.md)重排场景与既有视图，沿用 World Space uGUI、中文 TMP、原有命令和输入门禁。正式 HUD 隐去运行诊断，策划 HUD 保留；配置重载只在暂停菜单，结算与暂停遮罩隐藏局内控件。验收覆盖开始、召回、暂停恢复、失败／通关和配置错误，检查 540×960、1280×720 与运行中缩放、长版本和错误文字、UI 防穿透及失焦激活。下一 Windows 包需实际窗口复测。UI 测试 TearDown 停用自己加载的控制器以释放暂停，不修改生产暂停或受击测试等待行为。

## 音效调节实现

**源码已有的基线**是 `1170d50` 的 8 条素材与播放事件。普通受击限频 50 ms，普通碎裂限频 80 ms，目标碎裂复用碎裂素材且独立于普通碎裂限频。奖励和结算独立触发。发射只在首球出手时响，手动召回才播放召回音，过关音在回合结算时播放。

**本轮新增的合同**如下。

1. 工作台增设独立音效入口。默认素材可离线试听。每条提供音量、静音、换 WAV、试听及恢复默认，换素材保留音量和静音。输入接受可解码的单声道或立体声 WAV，最长 3 秒，转换为 48 kHz、16-bit 单声道 PCM WAV。试听使用转换后的同一份数据。无效或超长输入指出原因并保留原素材。[Web Audio 解码](https://www.w3.org/TR/webaudio/#dom-baseaudiocontext-decodeaudiodata)
2. `audio.json` v1 与已有两份文件分开导入导出。根包含 `schemaVersion`、`version`、`cues`。`cues` 以当前八个 WAV 的文件主名为键，每项含整数 `volumePercent`（0–150，默认 100）、布尔 `muted`（默认 `false`），以及可选的 `wavBase64`，只存换过的 WAV 字节。缺项使用默认，非法字段、未知槽位或损坏 WAV 给出槽位错误。工作台导出一份文件，策划手动替换游戏 `Config` 内同名文件。
3. 正式游戏和策划测试启动读取可选配置。缺文件采用内置音效。坏文件在启动时回退内置并显示音效错误，关卡照常按其配置加载。`FeedbackPlayer` 按现有事件选槽位，将该条倍率乘以现有增益，静音或音量为 0 时跳过播放。目标与普通块共用碎裂设置，各自保留原增益。
4. 仅策划测试的暂停菜单提供「重载音效」。先校验候选并创建替换片段，通过后再切换并显示版本。失败保留上一版和版本。删除文件后重载会恢复内置。切换时只清理旧音频播放与自建片段，保留场景内置素材、棋盘、关卡尝试、奖励、回合、球数和在途球。音效错误独立于关卡配置错误。[Unity 音频片段](https://docs.unity3d.com/6000.4/Documentation/ScriptReference/AudioClip.Create.html)

## 执行与验收

每项独立改动先做对应自测，通过后单独提交一次 Git，再开始下一项。代码、资源、配置和文档都适用。

| 批次 | 提交前验收 |
|---|---|
| 音效配置与游戏应用 | EditMode 覆盖默认、边界、损坏文件。PlayMode 覆盖静音、倍率、替换、成功切换、失败回退与删除恢复；暂停在飞行中切换后局面一致，原限频、目标结算、暂停和输入回归通过。 |
| 工作台音效页 | 从离线网页试听内置与自定义素材。立体声转换、调音、静音、恢复、导出并重新导入有效。坏文件保留当前编辑，关卡编辑与两份 JSON 导入导出回归通过。 |
| 正式关卡和主题 | 用策划确认的配置、真实奖励路线及新背景检查 3→4 和 6→7。直达、重排后按 ID 重载、失败重试、最终关和横竖屏安全区通过。 |
| Windows 随包验收 | 通过现有构建入口生成下一编号，带完整运行目录、工作台、试听用内置素材、`策划测试.cmd`、快速上手和来源记录。验证从实际包打开工具、导出、游戏重载和多球试听。记录构建号、Git hash、配置版本与实测结果。 |

历史包独立保留。正式九关、两张新背景未齐时，可先验收音效预览包，交付说明注明其内容状态。
