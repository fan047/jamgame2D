# 第 4–6 关紫晶背景去框与风格统一计划

## Context
美术提供了第 4–6 关的紫晶背景。用户只有当前展示图，希望交给 Locus 改图，使其与第 1–3 关背景的设计特点一致，尤其是无边框；紫晶应继续作为本阶段的区别，而不是全部改成青绿色。

本轮只交付计划和未修改的原图副本，不执行改图、导入、代码修改或构建。计划保存到 `Docs/中期版/第4-6关紫晶背景改图计划.md`；原图归档到独立目录 `Docs/中期版/美术原图_第4-6关紫晶背景/原图.png`，避免后续 Locus 依赖临时聊天附件路径。该目录只放原图，不放处理脚本或从中运行解释器；后续处理脚本放在项目 `Tools` 下并通过路径参数读取原图。

## 一、输入与视觉基准
- 输入：用户提供的 `5.png`，已读取实际格式为 **511×903、RGB PNG**。这是唯一可用输入，不假设存在 PSD、分层图或更高分辨率原图。
- 第一套参考：`Assets/Holedown/Art/Theme/background_game.png`，实际 **941×1672、RGBA PNG**。它只作为布局和风格规则参照，不能被覆盖，也不能直接复制大块青绿装饰到紫晶图上。
- 保留新图的深蓝洞穴、紫色水晶、蓝紫岩石、像素切面、中央空场；统一的是无框舞台、低对比边缘、中央可读性和分层逻辑，不要求两套同色或装饰一模一样。
- 第一套也存在过修补痕迹，不能照搬缺陷；最终以新图单独成立、两套切换自然为准。

## 二、最终目标
1. 四周没有连续的亮色矩形外框、描边或画框角，不是把亮框简单染黑后留一圈硬边。
2. 去掉顶部中央牌匾、金色圆环及其烘焙阴影/残影；发射器由游戏单独绘制，新图不再自带第二个发射器。
3. 去框后的四边自然收进深色洞穴，形成低对比、不连续的岩壁轮廓；角部与底边衔接自然，不留下规则切口、直角补丁或大面积同色盖板。
4. 保留紫晶主题及原有岩群的主要形状，不用全图模糊/滤镜破坏像素边缘，不随机增添装饰或新的框。
5. 岩石、水晶可以作为透明前景显示在场景最前；只提取实际装饰轮廓，不新增垫高岩层、挡墙或用于遮方块的宽底板。
6. 下方待上场预告仍由游戏绘制，不能把方块、数字、模糊预告、反弹线、召回提示或 HUD 画进背景。底边碰撞规则不因换图变化。

## 三、改图步骤

### 1. 原图保护与独立工作区
- 先读取原图归档及第一套参考，核对文件尺寸、颜色模式和当前项目状态。
- 保留原图归档字节不变，所有修图均输出到独立预览文件；不覆盖原图、第一套背景、其 `.meta/GUID`、用户字体、Logo 或 ProjectSettings。
- 使用已有可用的本地图像处理工具。若工具不可用，报告阻碍，不擅自安装依赖或用不透明矩形代替修补。

### 2. 为实际画框、牌匾和圆环建立局部遮罩
- 逐边辨认真实亮框及内外亮线，仅标记待去除的框体、顶中央牌匾/金环与烘焙残影。
- 给贴近边缘的紫晶尖端和岩石轮廓建立保护区域，不能用统一四周裁条误删水晶，也不能只按亮度/紫色阈值一刀切。
- 顶部牌匾/圆环使用独立遮罩，保留两侧紫晶；最终不要留下圆形光斑、牌匾轮廓或金色像素残点。
- 源图外围如有展示用的白边/黑边一并清理，但不得将整图裁小、改变内容比例或切掉底部岩石。

### 3. 用邻近洞穴材质局部补边
- 以同一侧邻近的暗蓝岩壁与洞穴颜色填补被移除的框体，优先沿实际岩壁方向延续，不把矩形条带、镜像重复水晶或第一套素材机械贴上去。
- 允许局部内容修补，但完成后做像素轮廓整理：边缘低对比、明暗方向一致、切面尺度连贯，消除平滑糊边、明显接缝、整齐阶梯墙和角部方块。
- 顶部中央补为低对比洞穴留白，给独立发射器与 HUD 留空间，不重新生成牌匾或装饰圆环。
- 中央原有空场尽量保持，不增加噪点、高光、裂纹、文字或新 UI。顶部紫晶先保留原位置；后续叠 HUD 检查，如干扰读数仅做必要的局部对比压低，不先改游戏布局。

### 4. 制作配套真实装饰前景
- 从改图结果中按明确物体轮廓提取紫晶及相关岩石，输出与本阶段背景**同画布、同原位**的透明 RGBA PNG。
- 前景中央及无装饰处透明，不以「补满缝隙」为理由填成墙，不把底部岩群抬到正式棋盘下沿，不凭空扩大遮挡面积。
- 背景中原有装饰可保留；同像素前景叠回时不应造成变亮、错位或光晕加倍。发光边缘不能重复混合成亮边，也不能把大片洞穴底色当作前景抠出。
- 导出前先做背景/透明前景叠回检查；未能干净分离时，不把失败的自动抠图当成最终交付。

### 5. 尺寸、像素和导出
- 新背景和其前景均保持 **511×903** 原生画布；前景透明、背景输出 RGBA（无透明需求的区域 alpha=255），不伪造高分辨率细节。
- 不直接把 511×903 非等比拉到 941×1672；两套共用舞台时保持纵横比、等比适配和相同锚点，极小宽高比差异通过外围暗色留白消化，不拉长水晶或岩石。
- Unity 导入沿用 Single、FullRect、中心 Pivot、PPU256、Point、Clamp、无 Mip、NPOT=None、默认无压缩的规则，禁用自动转 2 次幂缩放；每组背景与前景必须使用匹配画布及舞台变换。不能用第一套 941×1672 的前景强行叠到本阶段。
- 遮罩外不需要修补的区域保持原 RGB 像素；如有压暗 HUD 干扰区，单独标记修订范围，不能顺便整图调色。前景只覆盖真正的岩石/晶体核心，原图柔光可留在背景，避免把柔光重复叠亮。

## 四、输出与接入边界
- 新的最终美术文件使用独立路径：`Assets/Holedown/Art/Theme/background_stage_4_6.png` 与 `foreground_stage_4_6.png`；新资源有独立 `.meta/GUID`，同名资源若已存在先读取核对，不覆盖未知工作。
- 当前 `VisualTheme.Background()` 已将零基索引 3–5 对应第 4–6 关，使用 `backgroundStages4To6`；三组背景槽当前均为空，回退第一套。后续不能把新图写到通用 `background` 而影响第 1–3 关。
- 当前 `SceneVisuals.RefreshBackground()` 会随关卡选背景，但前景只有共享引用，`AlignForeground()` 只做变换对齐。**只更换背景会有误叠青绿前景的风险**；正式接入必须成对选择阶段背景与前景，并验证 3→4、6→7 的切换。此次改图交付不擅自扩展代码接口，图审通过后再安排接入。

- 必须先交付：原图/去框后同尺寸对比，顶部和四角局部放大，背景+前景叠回图，透明前景在浅/深棋盘格上的检查图。
- 确认改图预览通过后，才生成项目内独立的第 4–6 关背景和配套前景；不能覆盖第 1–3 关资源。
- 本次不添加第 7–9 关主题，不修改方块、球、字体、菜单风格、关卡数值或碰撞边界。
- 已有《待上场区与原生前景修改计划》继续作为待上场区/反弹规则依据，本计划只处理本阶段美术，不重新实现预告机制。

## 五、验收
- 无连续亮框、黑色硬框、顶部牌匾、金环或残影，四角和上下边缘无矩形补丁、复制接缝、重复水晶。
- 紫晶和岩石保持清楚像素轮廓，中央低对比；没有全图变糊、被迫改成青绿或无故丢失主要装饰。
- 背景+前景叠回与去框背景一致；只有真实装饰可以遮住方块，不新增底墙，不把透明区域误做成不透明。
- 单独看静态改图只能确认美术，不能声称游戏已验收。接入后需在同一游戏状态比较第 1–3 与第 4–6 关，确认发射器不重复、HUD/暂停/召回可读、待上场预告不被盖死，球仍按原底边反弹。
- 如获准接入，检查 540×960、720×1280 及 1280×720 横屏留边，确认等比显示、前景对齐和阶段切换。不得以网页拼图替代 Unity 实机。
- 不自动提交、推送或发布构建；列出实际输出文件、已核对项目和仍未验证内容。
