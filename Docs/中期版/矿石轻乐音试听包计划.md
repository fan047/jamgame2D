## 执行步骤
1. 检查工作区及目标目录，不覆盖已有目录；记录 `Assets/Holedown/Audio` 现有八条文件的校验和。先保存项目内计划文档，再准备独立输出目录。
2. 从合法、可访问的来源下载所需素材。当前素材站的 WebFetch 直连受限，不绕过安全限制；若官方不可达，仅使用能核对原作者、原文件和许可的公开镜像。无法确认授权或无法取得的条目明确列为缺项，不拿别的素材冒充。
3. 每个外部下载/压缩包放入新的空目录，检查归档路径后解压，不执行其中任何脚本/程序。处理脚本和工作目录与下载/解压目录分开；若使用 Python，必须使用隔离模式 `-I`。先检查可用转换工具；不为此改 Unity 配置或安装插件。
4. 保留完整原件，制作八类独立试听候选。优先输出 48 kHz、16-bit、单声道 PCM WAV，单条不超过 3 秒，以符合现有 `AudioConfiguration.DecodeWave()` 的替换规格；裁剪留完整起音、做必要的短淡出，避免硬截断与削波。不强行把各类声音做成一样响，重复受击应弱于奖励/结算。
5. 保留未加工备用片段和许可记录。注明哪些仅完成解码/技术检查、哪些经过实际播放；无真实试听能力时不宣称听感已验收，最终审美选择由用户试听确认。
6. 校验全部交付文件，生成 ZIP 并向用户提供试听文件及压缩包。整个过程中不修改 Unity 音效绑定或 `audio.json`。

## 验证
- 下载内容确实是音频/归档而非 HTML 错误页，归档无目录穿越路径，不执行下载内容。
- 每类候选均能解码，WAV 头部、采样率、位深、声道和时长符合规格；文件非空、非全静音，峰值不削波。
- 八个槽位各有对应文件；未获取成功的槽位明示，不能宣称完整八条已交付。文件名、来源、加工和授权能逐项追溯。
- ZIP 可正常打开，文件清单完整；若本机可播放，逐条做播放可用性检查，但不把技术播放成功等同于听感合适。
- 复核原 `Assets/Holedown/Audio` 校验和未变，场景、代码、音效绑定、字体、贴图和 ProjectSettings 未被本轮修改。
