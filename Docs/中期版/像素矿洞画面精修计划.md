## 当前优先问题
用户随后用截图明确指出两点，本轮先解决它们，不把一般美术精修扩大为整套重绘：
1. 方块压在左侧水晶上，希望水晶/岩石作为前景遮住方块；这里的「下面」是绘制层级，不是把方块向下挪。
2. 新方块在离底部较远的位置突然生成，希望从屏幕底部岩层后方自然进入游戏区域，而非半空弹出。

实现应区分逻辑网格生成与视觉入场：先核对现有行推进逻辑，通过前景层、遮挡和连续入场修正表现，避免为美术改变关卡、碰撞位置或回合规则。

## 推荐视觉方向
- 保留现有深蓝洞穴、灰蓝岩石、青绿水晶、橙金奖励及米白文字，不重绘 Logo、按钮、字体或整套方块。
- 水晶/岩石成为有真实轮廓的独立前景；方块主体与裂痕在后，血量/奖励标记、小球、击碎反馈和操作 UI 在前。
- 底部岩群上缘接近第 0 行下沿，向下连接原画底部，遮住约 0.12 世界单位的方块边缘；中央操作区保持可用。生成、升出、落定三态都要与岩层衔接，不能只叠图后仍留大段空隙。
- 保留 Build 20 的无亮框背景、无顶部牌匾、召回透明渐隐与开始点击不误发球。

- `Assets/Holedown/Scripts/Runtime/VisualTheme.cs` 及 `Assets/Holedown/Data/VisualTheme.asset`：共享舞台为 9.4×16.702232，中心取 `BoardCamera.StageCenter=(4,4.8)`，底边约 -3.551；目前只有背景引用，没有前景引用。
- `Assets/Holedown/Scripts/Runtime/BoardView.cs`：`CapturePositions()`、`PlayAdvance()`、`Advance()`、`StopAdvance()` 已有行移动、门禁回调和取消机制；新块起点目前是 `target + Vector3.down`。
- `Assets/Holedown/Scripts/Runtime/BlockView.cs`：`Bind()` 绑定网格目标位置；`SetPresentationVisible()` 只控制数字和徽记。
- `Assets/Holedown/Scripts/Runtime/GameFlowController.cs`：`BeginAttempt()` 首次直接 `Sync()`；结算路径与 `OnAdvanceCompleted()` 已有 `advancing`/`CanSimulate` 门禁。

- 已核对排序：背景 -20，方块 0，裂痕 1，数字 3，徽记 4，球 5，碎片 6，浮字 8。因此前景使用 2，不把整张背景抬到上层。

## 实现步骤

### 1. 增加与棋盘衔接的透明岩层前景
- 从当前 `Assets/Holedown/Art/Theme/background_game.png` 提取左侧水晶、边缘岩石和底部岩群，新增 `foreground_game.png`（941×1672 RGBA）及 Unity 导入元数据。中央透明，按物体轮廓遮挡，不用矩形盖板或按颜色一键抠图。
- 原背景及其 GUID 不变；前景保持同画布、中心 Pivot、FullRect、Point、无 Mip，避免透明裁边影响对齐。原位水晶与背景像素对齐；底部提取岩群重新布置/延伸，构成从舞台底边连接至第 0 行下沿的连续遮蔽区，消除悬空缝隙。不盖住块中心数字，不把水晶无限向棋盘中央延伸。
- `VisualTheme.cs` 和 `Data/VisualTheme.asset` 仅增加本次需要的通用前景引用，不新增未使用的分组前景/主题框架。
- 在 `Assets/Scenes/SampleScene.unity` 接入独立前景 SpriteRenderer，排序 2、无 Collider；由 `SceneVisuals` 复用当前舞台中心与背景缩放逻辑同步定位。UI 始终在前景上方。主菜单也核对前景与背景不重影、不遮挡开始按钮。

### 2. 让新方块从底部遮蔽区连续升出
- 在 `BoardView.PlayAdvance()` 中保留旧方块从捕获位置上移一行及现有 0.2 秒推进，不改规则层。
- 新方块起点改为根据共享舞台底边与该块实际显示高度计算：初始中心 Y + 半高必须低于舞台底边并留小余量；不再固定 `target - 1`，不硬编码屏幕坐标。
- 与步骤 1 的连续底部岩层配合，方块先完整隐藏在岩层后，再从岩层上缘自然露出，最终仍回到规则规定的第 0 行位置。数字与奖励标记在进入阶段保持隐藏，落定恢复；不通过淡入掩盖半空生成。
- 延用现有 `Advance()`、`StopAdvance()`、`SetPresentationVisible()` 和 `AdvanceCompleted`；不改变碰撞大小、棋盘坐标、每回合升一行的规则或输入语义。

### 3. 首次开局/重试复用同样的底部入场
- `BoardView` 增加首次入场入口，复用同一位置插值、停止/取消与完成通知；首次入场时长 0.45 秒，常规补行仍 0.2 秒。原始配置的各块目标行不变，不把整盘初始块强制改到 row 0。
- `GameFlowController.BeginAttempt()` 不再把初始方块直接瞬时展示；初始化 Session/Board 后就绪并置入场门禁，再进入 Playing 并开始呈现。动画完成前禁止发球与模拟、隐藏瞄准，暂停仍可用。
- 零时长与现有 `SkipAdvanceForTests` 入口必须直接同步并正常完成，不残留 `advancing`；检查同步完成回调顺序。重试、切关和退出先取消旧动画，旧完成回调不能解锁新一轮或留下隐藏数字。
- 不修改 `PlayerInputController` 的已按住输入保护，防止点击开始被当作首次发球。

### 4. 增补回归与实际画面验收
- 修改 `Assets/Holedown/Scripts/Tests/PlayMode/AdvanceMotionTests.cs`：以新 ID 区分真正补入的块，并先断言集合非空，避免空循环假通过；断言起始完整位于遮蔽区、入场途中连续、结束位置正确，旧块仍升一行，完成前不能发射。
- 新增首次入场的生产默认时长/输入门禁用例，并覆盖暂停冻结/继续、重试取消、零时长、跳过动画直达。保留开始点击不误发球测试。
- 修改 `PlaySceneEntry.StartIfReady()`，让需要已就绪棋盘的既有测试真实等待入场完成并沿用焦点恢复入口；动画用例专门捕获入场中状态，不统一禁用动画来制造通过。
- 复用 `StagePresentationTests`/`ThemePresentationTests` 验证前景层级、同舞台对齐、无碰撞体、块 Collider 和终点不变；对实际叠色截图确认水晶遮住方块底图/裂痕，但数字、徽记、球、碎片和 UI 清楚可见。覆盖普通/奖励/目标的方、横、竖九形及裂痕。
- 运行相关测试后再跑完整 EditMode/PlayMode 回归；通过现有本地 Unity 自动化取得本次主菜单及开局/补行起点、中段、落定的实机截图或短录屏。截图呈现结果不能代替逐帧动画断言。
