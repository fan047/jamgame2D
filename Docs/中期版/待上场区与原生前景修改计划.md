# 待上场区与原生前景修改计划（新版）

## Context
用户否定 Locus 做出的底部深色遮挡墙，澄清目标并非「额外造岩层，把方块盖住」，而是：现有岩石、水晶装饰位于场景最前；下方未上场的方块在待上场区无数字、模糊、渐进地显示。用户同时要求保留球的触底反弹。

本计划替代《像素矿洞画面精修计划》中「垫高岩层覆盖第 0 行」「从舞台底外飞入」「整盘首次升出」的做法；其他防误发、暂停、规则与资源保护要求继续有效。

本轮只交付修改计划，不执行游戏修改。完成版保存为 `D:\Unity\UnityHub\Projects\jamgame2D\Docs\中期版\待上场区与原生前景修改计划.md`，供 Locus 按此实施。旧计划保留追溯，不要求两个方案同时满足。

## 一、最终画面与交互约定

### 1. 正式场、反弹底边与待上场区分离
- 正式方块仍位于原 8 列棋盘；第 0 行方块显示范围约 y=0.05～0.95，规则坐标不变。
- 保留 `SampleScene.unity` 中现有 `Bottom` BoxCollider2D：位置 y=-0.25、厚 0.5，其顶面为 y=0。沿用 `Bounce.physicsMaterial2D` 的 friction=0、bounciness=1，不改材质、碰撞层或边界。
- 球在 y=0 的正式底边反弹，不进入下方预告区；不把底边改成回收触发器。球中心的接触高度应计入实际半径，默认约 y=0.12，而不是让球心到 y=0 才反弹。
- 待上场区默认只预告**下一排**，放在底边以下、召回操作上方，与正式棋盘同列对齐；竖屏初始参考范围 y=-1.05～-0.15，最终以实际文字边界校正，不能挤进正式场。
- 底边用细、低对比的接触线说明反弹位置，不加厚地面、不加亮框、不再遮住整片底部。接触线只是显示对象，不新增碰撞面。

### 2. 岩石和水晶只保留原有轮廓
- 继续使用现有去框背景，不恢复亮框，不重绘整个背景。
- 重做 `foreground_game.png`：只从当前背景**原位提取真实岩石、水晶轮廓**，不移动、不抬高、不延伸成挡墙，不复制矩形条带，不用实色填满中心空隙。
- 透明区域仍然透明；原图没有装饰的中央区域不能凭空变成不透明地面。前景保持 941×1672、中心 Pivot、FullRect、Point 和相同舞台变换，防止重影与比例错位。
- 岩石、水晶是场景最前景，覆盖其真实轮廓后方的方块、数字及预告；UI 仍在最前以保证操作。当前世界对象最高排序为浮字 8、世界 Canvas 为 20，前景排序改为 10，不再使用穿过方块数字的排序 2。
- 不扩大装饰来追求遮挡量；关键方块中央读数与主要球路不能被新造装饰遮住。

### 3. 待上场方块的「模糊渐进」定义
- 显示真实下一排的列位和宽度轮廓，但不显示血量数字、奖励 +N、目标标记或奖励/目标专属颜色；统一用低饱和灰蓝色轮廓。
- 同一轮廓靠近正式场的一侧相对清楚、稍亮；向下逐渐更模糊、更暗、更透明，消失在原有洞穴背景中。不是给整个底部铺一块灰黑矩形，也不是把整个游戏画面模糊。
- 等待时保持稳定预告，不因玩家拖延而不断变清晰或泄露更多信息。首次展示可短淡入，但不要周期闪烁或反复呼吸干扰瞄准。
- 真正推进时，预告所在那排沿相同列位连续升到 row 0，轮廓由模糊过渡为正式样式；完全到位后才显示数字及角色标记。
- 默认仅一排预告，不增加多排远期信息，不改关卡生成顺序。空排正常保持空白，不跳过空排显示更后面内容；队列耗尽时不造占位方块。

## 二、当前实现问题与应复用部分
- `Tools/BuildForegroundLayer.py:101–162` 当前通过矩形拼接和实色填缝生成了墙；这不是排序错误。该流程需改为真实轮廓提取，不能在旧墙上增加模糊或渐隐来掩盖。
- `SceneVisuals.AlignForeground()` 已能与背景同步变换，可保留；`VisualTheme` 已有通用前景引用，不新增第二套前景系统。
- `BoardView.CapturePositions()`、`PlayAdvance()`、`Advance()`、`StopAdvance()` 已具备旧方块位置捕获、暂停冻结、取消、完成事件，继续复用。
- Locus 新增的 `EntryY()` 从舞台外约 y<-4 起步、`PlayEntry()` 整盘 0.45 秒入场，与待上场区方案不符。针对性替换相关呈现，不整文件回滚、不使用 git reset/restore 覆盖其他工作。
- `BoardState` 私有深拷贝补行队列；`IncomingCursor/IncomingCount` 只读，但尚无下一排只读查询口。`Advance()` 仍是旧块 Row+1、新块 row 0，逻辑保持。
- `GameFlowController.Changed`、`RoundSettled`、`AttemptReset` 与 `OnAdvanceCompleted()` 可复用；注意 RoundSettled 发出时游标已经前进，不能把它当成「推进前」数据来源。

## 三、实施步骤

### 1. 清除错误造墙方式，恢复真实装饰前景
修改 `Tools/BuildForegroundLayer.py` 的生成策略，删除造墙条带、阶梯平顶和中心实色填补；以明确的装饰轮廓遮罩从当前背景复制原位像素。输出保持原尺寸和既有前景 GUID，背景、用户 Logo、中文字体与 ProjectSettings 均不覆盖。

在 `Assets/Scenes/SampleScene.unity` 调整现有前景到场景排序 10，保持 UI 排序 20；不加 Collider。`SceneVisuals` 延用共享舞台对齐。先在无方块和有方块两种画面确认：没有新墙、矩形边、漏抠蓝边或额外岩群，背景叠前景时原有装饰外观不应明显改变。

### 2. 增加不会消费队列的下一排查询
在 `Assets/Holedown/Scripts/Rules/BoardState.cs` 增加最小只读查询，例如 `TryPeekIncomingRow(out IReadOnlyList<IncomingBlockPreview> row)`：
- 返回独立快照，元素仅含 Column、Width；补行高度固定 1，不返回可变 `RowDefinition/BlockDefinition`，不暴露 Health、RewardBalls、IsTarget。
- 返回值区分「存在但为空的下一排」和「已耗尽」；调用不改变 IncomingCursor、Blocks、块 ID 或生成顺序。
- 不为了预告提前调用 Advance、创建真实 BlockState 或复制一套关卡读取/随机生成逻辑。

### 3. 增加纯显示的待上场预告
新增 `Assets/Holedown/Scripts/Runtime/IncomingRowPreview.cs`，仅维护下一排快照、预告 SpriteRenderer 及显示状态，挂到棋盘呈现层并由 `BoardView` 协调交接。
- 不复用带碰撞和数字的整套 Block Prefab 来伪装预告，不添加 Rigidbody2D/Collider2D/Hit/血量脚本。
- 使用普通方块形状的 alpha 轮廓和统一色，不把奖励/目标贴图颜色提前显示出来。
- 新增专用 `IncomingPreview.shader` 与共享材质，沿用当前 `SpriteFlash.shader` 的 URP 2D Sprite 渲染方式；只对预告做局部轮廓柔化、纵向透明渐变与清晰度控制，不使用全屏后处理，不影响正式方块材质。
- 模糊尺度按世界尺寸/显示比例校正，不能只在一张截图尺寸下有效；裁剪柔边不得越过 y=0 混入正式球路。
- 预告区使用世界棋盘列坐标，随现有共享舞台缩放；召回按钮与提示在下方独立保留。沿用已有 `SoftScrim`，不添加新的不透明底板。

### 4. 把预告与真实入场接成一次连续过渡
由 `BoardView` 协调，`GameFlowController` 保持推进决策及门禁：
1. 瞄准/发射期间维持当前下一排快照，不因 Changed 事件重复刷新或重建。
2. 真正推进前保存该快照；规则仍正常 Advance 一次。根据本次新块 ID 和列位，将其起点设为对应预告中心，而非舞台底外或任意空中位置。
3. 在同一呈现切换中隐藏旧预告，接续显示入场块，起始位置、轮廓、模糊程度保持一致，避免两套对象叠加或预告先跳到下一排。
4. 入场块只在过渡期间使用预告外观，升入正式区域时逐渐清楚并恢复角色贴图/原有材质，数字和身份标记在落定后显示。旧正式块仍上移一格，常规推进沿用 0.2 秒，期间禁止发球和模拟。
5. 完成后清理过渡状态并查询新游标的下一排，更新待上场区；入场前后的目标位置、碰撞尺寸和规则都不改变。

无下一排、空排或胜负时不要凭空生成预告。暂停冻结真实过渡；重试/切关/重载/退出先取消旧动画和预告缓存，旧完成回调不能影响新局。

首次开局的正式棋盘按配置目标位置展示，不再让整盘从舞台底端飞上来；初次仅为待上场预告做短淡入。移除与旧全盘入场绑定的门禁/测试假设，保留开始点击不误发球及既有补行门禁。不得为了常驻预告在下方创建或保留正式物理碰撞体；交接期间的真实块由原有推进门禁隔离，落定并校准 Collider 后才恢复模拟。

## 四、反弹与物理验收
- 保持现有 `Bottom` 的位置、尺寸、材质和 Layer 不变。真实球与真实方块照常碰撞，预告永远不能被击打、扣血或计奖励。
- `AimInput` 的预测查询不能命中预告；向正下方瞄准时，默认半径对应的球心首接触仍约 y=0.12。
- 除沿用 `PhysicsTests.BallsBounceHitAndReturnAtBothSpeeds` 外，补一个**底边独立反弹**用例：选择没有真实方块挡路的位置，证明球不是碰到方块才被判断为「反弹成功」。
- 覆盖速度 12/24、垂直与斜向下发射，断言触底前 Vy<0、触底后 Vy>0、速度幅值保持、球不进入预告区；无额外 Hit/血量/奖励/回收事件。
- 可见球与原装饰有局部遮挡时不影响物理；检查主要触底接触点可辨认，不能再用宽大的不透明图层遮住整条反弹带。
