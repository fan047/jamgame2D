# 后六关矿洞素材接入方案

2026-11-10。以构建 22 为基线，执行已确认的两组接入。第 1–3 关使用现有青晶主题，第 4–6 关使用 2 号紫晶素材，第 7–9 关使用 3 号玫红金晶素材。

## 输入与处理

四张原图归档在 [后六关矿洞素材原图](后六关矿洞素材原图) 内。2 号、3 号背景均为 941×1672，方块展示稿均为 3508×2480。两组以本批完整分辨率原图为加工输入。组 2 与组 3 各产出一张背景、一张前景、九张方块底图。

- **背景**。以每张图的独立局部遮罩清除连续亮框、顶部牌匾和烘焙金环。延续各自的暗色岩面，让四边自然收成断续岩壁。保留原构图、水晶位置及画布。局部压低顶部紫晶和底部金晶高光，维持原有色相。
- **前景**。从处理后的同组背景复制原位岩石和水晶像素。前景使用同画布和坐标，装饰之间透明。保持构建 22 的场景排序 10、UI 排序 20。3 号右下大金晶原位进入前景，真实轮廓内允许遮挡方块、数字、徽记与短暂经过的小球。以前景同原图逐像素叠图、空隙透明及游戏画面核对覆盖范围。
- **普通块**。从对应展示稿裁取原生方、横、竖形，修整粘连、残边及彩条，2 号保留紫灰，3 号保留粉紫。保留像素边缘、现有视图的占格与光照方向。
- **特殊块**。图册的 6 位对应目标，10 位对应奖励。清掉示例数字和嵌入徽记后修复干净的横块块面，沿用切面拼接补方形和竖形。两组奖励用橙金、目标用青绿。现有独立徽记、裂痕、碎片与星光供两组共用，动态数字沿用游戏绑定。导出有透明边的独立 PNG，做浅深双底与九形对照。

## Unity 接入

- 复用 `VisualTheme` 的分组背景槽，为第 4–6 和第 7–9 关各配一组原位前景与九形底图。由当前关序统一路由，`SceneVisuals` 在同一次刷新中设置背景与前景。新背景与前景使用现有 Point、PPU 256、中心 Pivot、FullRect、无 mipmap 的 Sprite 导入规格，并采用同一舞台变换。
- 首次同步棋盘前将当前关序传给方块视图，正式进关、策划直进、重载和重试使用同一路径。分组背景缺失时回退青晶整组；背景存在但专属前景缺失时隐藏前景；个别方块缺失时使用现有同角色、同形状底图。交付时两组引用齐全。
- 待上场预告及交接沿用构建 22 共用的灰蓝轮廓与现有材质，落定后显示本组正式块面、数字和徽记。按现有棋盘、底边反弹、UI 输入和关卡数据规则接入。

## 验收与交付

- 保存去框前后、前景叠图、两组九形方块对照。检查去框和金环修复痕迹、透明轮廓、白黑边、数字残留和角色色。确认源文件与归档原图字节一致。
- 复用已有分组背景、策划模式和待上场区测试。覆盖第 3→4、6→7 关、策划跳关、同关重载、重试、背景回退、专属前景空槽及单张块图回退。核对组资源成套切换、预告升入第 0 行和球在正式底边反弹。
- 在 540×960、720×1280、1280×720 获取真实 Game 画面。检查 HUD 与召回、金晶遮挡边界和球离开装饰后恢复可见的过程。截图注明实际采集方式。
- Locus 先核对工作区与正在运行的任务，保全用户及其他任务的改动。每项独立改动自测通过后分别提交 Git。使用下一空闲编号交付 Windows 构建，记录实际包含的变更、提交、测试结果与截图路径。交付后由主线对照方案复核。
