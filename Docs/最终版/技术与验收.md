# 水晶矿洞 · 技术与验收

## 架构与状态归属

工程使用 Unity 6000.4.3f1、`SampleScene`、World Space uGUI 和中文 TMP。规则层、运行时协调层与表现层继续各自承担职责。

| 层 | 主要组件与职责 |
|---|---|
| 规则 | `GameSession` 管单关回合与结算，`BoardState` 管占格、伤害、补行和越线，`CampaignState` 管跨关奖励与入关球数。 |
| 协调 | `GameFlowController` 管尝试生命周期、配置快照、暂停、重试、切关和命令队列。`PlayerInputController` 处理输入门禁、焦点恢复与 UI 拦截。球回调按尝试、发射轮次和活动球身份校验。 |
| 表现 | `BoardView`、`BlockView`、`IncomingRowPreview` 呈现棋盘及补行。`VisualTheme` 和 `SceneVisuals` 选择与对齐主题。HUD、弹层及 `FeedbackPlayer` 消费有效事件，呈现画面和声音。 |

重试与切关重新生成棋盘。推进时锁定瞄准和模拟，暂停冻结局内动画。切关、重试和重载会清理旧推进、预告与反馈。弹层过渡使用非缩放时间，输入权限随状态生效。

## 外置配置

| 文件 | 约定 |
|---|---|
| `settings.json` | `schemaVersion=1`。构建 23 包内为 `mid-1`：基础 12 球、半径 0.12、速度 12、发射间隔 0.06 秒、最大瞄准角 80°、自动召回 20 秒。源码 `Config` 在打包后改为 `demo-1`（间隔 0.07、自动召回 30 秒），下次构建随包生效。 |
| `level.json` | `schemaVersion=2`。按数组顺序推进，稳定 ID 唯一。改名与重排保留 ID，新增与复制生成新 ID。兼容旧单关 v1，工作台统一导出 v2。 |
| `audio.json` | 可选，`schemaVersion=1`。独立读取，覆盖所有关卡的音效。根对象包含 `version` 和 `cues`，各槽位可填 `volumePercent`（0–150 的整数）、`muted`、`wavBase64`，缺项使用内置素材、100% 音量和非静音。文件上限 4 MiB。 |

球参与关卡成对加载。正常启动时两份均缺失会使用内置回退，缺一份或非法时显示配置错误。正式「重载并重开」读取磁盘并回第 1 关，「重新开始全程」使用已加载快照。策划「重载当前关」先验证两份文件、稳定 ID 和有效球数，再提交候选并重建本关。失败保留原局。基础与满前奖模式按新配置重算，手填模式保留手填值。

初始块 `row`、`column` 为 `0–7`，底部为 `row 0`。补行的局部 `row=0`、`height=1`。工作台与 C# 都校验越界、重叠、唯一目标、最终关奖励和累计球数溢出。批量改值作用于当前布局组的选中项，经预览后整批应用并可一次撤销。属性草稿在跨组、跳转和导出前明确处理。

## 主题、前景与补行

- `VisualTheme` 使用现有 `backgroundStages1To3`、`backgroundStages4To6`、`backgroundStages7To9` 槽。后两组是否启用由对应背景槽决定。背景缺失时整组回退青晶，青晶背景槽为空时用通用背景。专属背景存在时，缺前景则隐藏前景，缺单张方块则回退到青晶同角色、同形状底图。
- `SceneVisuals` 在同一刷新中选择背景与前景。`GameFlowController` 在棋盘首次同步前下发关序，正式流程、策划直进、重试和重载共用该路径。背景与前景保持 `941×1672` 同画布、同坐标，导入用 Single、Point、中心 Pivot、FullRect、PPU 256。
- [后六关原图](../中期版/后六关矿洞素材原图)与[处理脚本](../../Tools/BuildLateStageThemes.py)保留重制依据。背景以局部遮罩去掉连续亮框、牌匾和烘焙金环。前景从处理后的同组图原位提取，叠回底图时保持像素对齐。普通三形来自各自图册，目标 `6` 与奖励 `10` 横块清理示例数字和徽记后补出方形及竖形。
- 正式底边碰撞顶面在 `y=0`，默认球心在离底面约 0.12 处折返。底边接触线仅供显示。`BoardState.TryPeekIncomingRow` 只读返回下一行的列位和宽度，不消费游标。空行保持空白，耗尽时移除预告。
- `IncomingRowPreview` 是纯显示对象，中心 `y=-0.55`，无碰撞体与刚体。推进约 0.2 秒，补行用共用灰蓝轮廓从预告位置升入，落定才切正式图和标签。前景排序 10，UI 画布排序 20。推进、金环脉冲、拖尾、碎片和弹层参数通过现有 Unity Inspector 调整。

## 音效契约

| 槽位 | 触发 |
|---|---|
| `volley_launch` | 每轮首球出手时一次。 |
| `block_hit` | 命中且方块仍存在。普通受击限频 50 ms。 |
| `block_break` | 普通块或目标块被打碎。普通碎裂限频 80 ms，目标碎裂独立触发，共用素材和覆盖配置。 |
| `reward_break` | 奖励块击碎并出现 `+球`，各奖励数值共用一条。 |
| `stage_clear` / `stage_fail` | 本轮结算为通关或失败时各播一次。 |
| `manual_recall` | 玩家主动召回生效时一次。 |
| `ui_confirm` | 开始、暂停、继续、下一关、重试等按钮命令生效。召回使用自己的音效。 |

工作台接受可解码 WAV，换音后以 48 kHz、16-bit、单声道 PCM WAV 试听和导出，单条最长 3 秒。运行时将槽位音量乘到既有增益，静音或 0% 跳过播放。启动读取失败使用内置并提示。策划暂停中的「重载音效」在完整校验后切换，同一局继续。重载失败保留上一版，删除文件后重载可恢复内置。

游戏内音量设置将循环背景音乐和全部音效分开调节。滑杆为 0–100%，0% 静音，默认音乐 70%、音效 100%。游戏即时应用音量并保存到本机 PlayerPrefs，策划的单槽音量继续叠加到音效增益。该功能、循环背景音乐与新的胜负音效由提交 `bc485b4` 加入源码，**打包于其前，构建 23 的包内不含**；下次构建随包生效，届时重跑 PlayMode 并更新交付说明中的用例数。

## 验收与提交

每项独立改动先完成对应自测，再单独提交 Git。提交前核对暂存范围。新 Windows 包使用递增编号，随包保存构建结果、配置版本、提交号、测试结果、验证画面和 SHA-256。

| 改动 | 对应验收 |
|---|---|
| 规则、配置与工作台 | 校验 v1/v2、非法配置、稳定 ID、奖励确认、正式 3→4 与 6→7、失败重试、最终关和策划跳关。验证导入、批量改值、撤销、导出及游戏内重载。 |
| 画面、动效与 UI | 覆盖 540×960、720×1280、1280×720 及运行时缩放。检查前景叠回、真实轮廓遮挡、球离开装饰恢复可见、底边反弹和预告转正。回归开始、召回、暂停、配置错误、点击拦截及失焦恢复。 |
| 音效 | 验证八槽位触发、密集连击、目标碎裂与结算先后、换 WAV、静音、倍率、坏文件回退和同局重载。试听候选需在实际游戏中确认。 |
| Windows 发布包 | 使用完整解压包验证启动、策划入口、配置重载及局内操作，核对包内关键文件哈希，排除 `*_DoNotShip`。将窗口实测、编辑器 Game 渲染和自动化断言分别记录。 |

构建 23 的历史证据为 EditMode **125/125**、PlayMode **89/89**，Unity 构建 **0 错误、486 警告**。完整用例、证据来源和实际窗口覆盖见[构建 23 交付记录](../中期版/构建23交付说明.md)。
