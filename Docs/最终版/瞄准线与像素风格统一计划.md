# 水晶矿洞 · 瞄准线与像素风格统一计划

2026-11-10 已确认方向，待实施。以构建 23 的青晶、紫晶和玫红金晶主题为画面基线，以当前源码的界面与交互为接入基线。画面统一使用背景已有的硬边像素、阶梯轮廓和矿石切面，沿用各主题基色及现有颜色职责。

## 瞄准轨迹

* 使用连续的金黄色光束，取发射小球的主色、中间色与高光，参考图用于确定粗实线形态。以 540×960 下约 13 像素宽为试装目标，宽度随舞台等比缩放。边缘和末端呈像素阶梯，亮度以三组背景上都能读清球路为准。
* 沿用 `AimInput` 的发射点、实际球半径和首次碰撞预测。光束末端对齐球心首次接触的位置，鼠标移动时整条线即时转向。光束宽度是表现参数，碰撞仍由实际球半径决定。
* 有效瞄准时整条底光保持可见，一小段亮光从发射点沿线向前扫，在末端淡出并循环。发射、暂停、鼠标离开有效区域或悬停 UI 时，底光和动画一起隐藏。首球出手继续使用已有金环脉冲。
* 光束位于方块底图与裂痕之上，血量数字、身份徽记、小球和原位矿洞前景继续处于各自的上层。

## 字体、方块与界面

|范围|做法|
|-|-|
|字体|方块血量、HUD 数字、标题和按钮短字采用像素字。小号中文说明、策划诊断和长错误提示沿用清晰的中文字体。用实际字表核对 `0–9`、`+`、`/` 和短按钮所需中文，保留中文回退。|
|三组方块|统一像素颗粒、外缘台阶和矿石明暗切面。普通块沿用各组基色，奖励保持橙金，目标保持青绿。血量中心保持干净。普通、奖励、目标的方、横、竖形沿用现有占格和碰撞边界，裂痕与徽记继续独立叠加。|
|UI 组件|面板与按钮使用同一像素尺度、阶梯切角和少量分明的高光。沿用深蓝与蓝灰面板、象牙白主要操作、橙金奖励等现有颜色职责。文字、图标、命中区域和按钮状态由现有界面组件管理。|

像素字资产取自 `https://github.com/Astro-2539/ZLabs-Pixel-12px`（OFL-1.1，仓库只提供 `.kbitx` 源文件，取 Release `Build_20260519` 的 `ZLabsPixel_12px_M_CN.ttf`）。位图字体只有在渲染像素接近取样档位时才保持硬边，因此按两档取样：`ZLabsPixel12`（12 像素档，光栅模式 + 点采样）用于方块血量与 HUD 数字，`ZLabsPixel24`（24 像素档）用于标题与按钮短字，两者都以中文字体 `ChineseUI` 作为回退。渲染后不足约 20 像素宽的小号中文（关卡、每轮球数、第 N 轮、暂停、召回、目标已击碎）继续直接用中文字体，避免笔画断裂。

## 试装与验收

1. 先在青晶关做一屏实机对照，包含运动中的瞄准光束、普通／奖励／目标块、HUD 数字与暂停弹层。确认粗细、明暗、像素尺度和中文可读性后，将同样的视觉规则应用到紫晶及玫红金晶组。
2. 在 540×960、720×1280、1280×720 及运行中缩放下检查线宽和像素边缘。实测正向、斜向、窄缝与靠边瞄准，核对终点与首次碰撞、亮光方向和末端淡出。回归发射、推进、暂停、UI 悬停、留边与失焦恢复。
3. 核对三组普通／奖励／目标块的角色色、三形轮廓、三位数血量与中文按钮。检查暂停、设置、胜负结算和长配置错误的文本、状态、点击区域与响应式布局。
4. 保存三组对照截图和一段瞄准过程录屏。素材交接记录原图、输出切片、对应控件和加工步骤，验收记录注明实际采集方式。
