Holedown 多关卡与策划测试版 策划快速上手（不需要 Unity）

每次构建单独保存在 Builds/01、Builds/02……，本运行目录位于对应编号的 Windows 子目录。
新构建不覆盖旧包；升级时需手动将旧包的 Config 复制到新包，先备份，height=2 配置必须使用 P1 程序。

1. 运行 HoledownGrowth.exe，配置校验成功后显示开始页，点击 Start 进入第 1 关。
   左键按下发射一轮，按住不会连续发射；Space 或 Recall 按钮召回。
   Esc 或 Pause 按钮暂停；使用 Continue 明确继续，Esc 不负责继续。
   切出窗口会自动暂停；返回时首次点击只激活窗口，抬起后重新点击 Continue 恢复。
   暂停页 Reload + Restart 会放弃本轮、读取文件并从第 1 关重开，不回开始页。
   已接入构建 05 的矿洞正式游戏素材；音效及正式 UI 流程仍沿用现有占位。
2. 双击 PlannerEditor/index.html，用 Chrome 或 Edge 打开离线编辑器。
3. 在编辑器里同时导入本目录 Config/settings.json 和 Config/level.json。
   刚打开编辑器时显示的是内置示例，不会自动读取游戏当前文件。
4. 选择关卡，使用整关总览：上方为 8×8 初始棋盘，下方按顺序列出全部补行，八列对齐，空补行保留，最后一条有标记。
   总览内可垂直滚动；“跳到布局”下拉只跳到指定组，不隐藏其他组。初始棋盘顶部 row 7、底部 row 0，补行均用局部 row 0；排列表示补入顺序，不是游戏中同时存在的位置。
   点击任意组中的块可直接跨组编辑，右侧当前位置、属性和数值表同步。窄窗口时属性区在总览下方。
   点击空格按所在组的局部坐标新增；虚线放置预览只出现在当前组。长数值可从属性、数值表或方块悬浮提示查看完整值。
   表格血量和球参数失焦/Enter 提交，Tab/Enter 连续改血；普通改值保留总览滚动位置与选择，不自动跳到组首。
   位置、形状、类型需点击应用。跨组、跳转和导出前，未应用属性需选择应用、丢弃或取消；错误数值可按 Esc 取消。
   批量操作仅作用于“作用范围”标出的当前布局组；切换组会清空旧组勾选，不会批量修改整关。
   新增／删除补行、撤销／重做会同步总览、跳转项和当前位置；错误定位会选择对应关与组并滚动定位。
   支持新增、复制、删除、前移／后移与关名修改。新关分配唯一 ID，改名和重排保留 ID；新增未完成关需补齐唯一目标后才能导出。
   血量、奖励可批量设值／加减／乘倍率，倍率四舍五入。先检查预览，整批全成或全败，一次撤销，最多 50 步。
   可只选普通／奖励／目标块；奖励为 0 表示普通块，正值表示奖励块。目标必须唯一且位于最后一条补行，目标不能兼任奖励，最终关不能放奖励。
   非最终关允许多个奖励块，每块为合法正 Int32 整数；+3/+5/+8/+10 是快捷值，不是取值限制。自定义奖励和多奖励配置必须配套本新版程序，旧 P1／构建 05 不支持。
   形状为 1×1、2×1、1×2；竖块仅限初始布局，从 row 向上占两行。入关球数显示无前奖最低值和拿满前奖最高值，不代表中间每个整数都可达到。
   名义最后一球时间为（球数-1）×间隔；达到自动召回时间只提示可能发不完，不阻止合法配置导出，实际受帧率影响。
   校验通过不等于通道可玩，仍需实射测试。
5. 修改球参数版本/关卡版本，分别下载 settings.json 与 level.json。
6. 把下载的两份文件替换到游戏 Config 文件夹，名字必须完全一致。
   浏览器下载不会自动更新 Config；注意不要留下 settings (1).json 这样的文件名。
7. 切回游戏点击 Reload + Restart，当前局会被丢弃，新局读取刚保存的配置。
8. 检查 HUD 的 Config: S:版本 / L:版本，再开始测试。只有配置改变时不需要重新构建游戏。

配置约定：settings schemaVersion 为 1，level 导出为 2；旧单关 v1 可导入并转换为单关 v2。
不要把成长版 v2 配置交给旧 MVP 程序。version 为 1–32 个英文字母、数字、点、下划线或连字符。
球数、血量使用正整数；数值必须为有限正值；半径小于 0.5、角度小于 90。
默认球直径 0.24，不能通过只有 0.1 宽的标准块缝，请留出真实可通行空间。
初始行号为 0–7，底部为 0；补行内 row 一律为 0、height 必须为 1；列号为 0–7。
竖块完整占两行，不可重叠或超出顶部；推进后顶端进入第 8 行即失败。
受击时只有图形轻微缩放，碰撞体和文字不缩放；剩余血量 ≤2/3 显示轻裂痕，≤1/3 显示重裂痕。
比例以初始最大血量计算，推进不重置裂痕；工具不会自动替你重写现有布局。

可选竖块演示：先备份 Config/level.json，将 Config/Examples/level-vertical.json 复制为 Config/level.json，
点击 Reload + Restart；HUD 关卡版本应为 growth-p1-example，第 1 关 column=4、row=1 有 6 血竖块。
演示文件不能直接按原名导入工具，请先复制/重命名为 level.json，再与 settings.json 一起导入。
height=2 配置需要本 P1 程序；旧 P0 成长版程序会明确拒绝，不能只更新工具不更新游戏。
每轮结算先判断目标胜利，否则上移补行并判断越线失败。

成长规则：奖励块完全击毁后暂存，过关后才确认；本关球数不变，下一关才增加。
Next Stage 手动进下一关；最后一关显示 Run Complete。
Retry Stage 仅失败后可用，保留入关球数、丢弃本次暂存奖励。
Restart Run 从已载入快照的第一关重开，不读取修改后的文件。
只有 Reload + Restart 或重新启动程序才读取文件；重载会清空整轮成长。

策划指定关测试（显式进入，与正式流程分开）：
- 双击 exe 同目录的“策划测试.cmd”，或给同一 exe 加 --planner-test 参数。不要把脚本放到 PlannerEditor 内运行。
- 用 Previous stage／Next stage 选择关卡 ID，Change ball mode 切换方式：Base balls only（默认，无前关奖励）、All previous rewards（拿满前关所有奖励）、Manual entry balls（手填正整数）。
- Start selected stage 从所选关的初始布局开始，HUD 显示实际关序与本次生效球数，手填不会改正式基础数值或 JSON。
- 暂停后 Reload current stage 读取两份配置并按稳定 ID 找回同一关；无前奖／满前奖方式按新配置重算，手填方式保留原手填值。
- 损坏、缺文件或当前 ID 被删除时显示错误并保留旧局及暂停状态。修好文件后可以再次重载；即使两个文件同时缺失，测试重载也不会悄悄使用内置配置。
- 测试通关／失败可 Retest stage，或 Stage selection 返回选关；不会自动推进正式成长流程。关卡重排后“拿满前奖”按新顺序计算。
- 普通双击 exe 仍走 Start，从第 1 关按真实击碎并确认的奖励依次推进；正式模式 Reload + Restart 仍从第 1 关重开。

错误处理：
- 两个 JSON 都不存在：使用内置默认配置，HUD 显示 Built-in。
- 只缺一个、JSON 损坏、字段拼错或关卡非法：显示 Config error，禁止发射，不悄悄回退。
- 数组下标从 0 开始；incomingRows[1].blocks[2] 指第 2 条补行的第 3 个方块。
- 修正文件后点击重载；启动前错误修复后回开始页，游戏内错误修复后直接从第 1 关开始。
- 修改文件不会影响正在飞行的一局，必须主动重载或重新启动。

请先备份原文件；编辑器关闭或刷新前确认已导出。“已请求导出”不是已保存到游戏，请核对下载。
settings 和 level 独立提示修改/导出状态。游戏不会把伤害和推进写回 JSON。
程序重建时保留输出目录已有 Config 文件，不覆盖策划调参；需要恢复示例可在编辑器里还原默认后重新导出。
不要修改 Data、MonoBleedingEdge、DLL；请把整个运行目录一起拷贝，不能只拷贝 exe。
